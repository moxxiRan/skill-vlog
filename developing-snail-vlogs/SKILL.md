# 蜗牛拟人 VLOG 内容开发

## 核心原则

先选择一件观众自己也愿意经历的真实活动，再让蜗牛进入。把行程当骨架，把途中发生的微事件当内容。

事件型桥段优先使用这一链条；没有物理后果的体验不强行制造事故：

> 现实动作 → 环境施力或变化 → 即时反应 → 可见结果／持续状态 → 处理恢复、关系反应或安静余波 → 继续

让角色像朋友一样共同生活，不把角色当成等待展示的功能卡。画面负责交代动作、因果、结果和持续状态；台词格负责补充观察视角、朋友关系、人物口吻与笑点，不是角色配音或真人旁白。静音测试只检查主要事件是否仍然可懂，不能据此删除有效台词。先证明内容有趣，再评估制作方式。

### B／干嘛猫一日故事引擎（故事大纲内规则）

当制作模式为 **B／干嘛猫模式**，且故事跨度为单日或跨日旅行时，先在故事大纲层设计故事弧，再进入角色情节和 Storyboard。这里迁移的是五条样本归纳出的工作模型；附件和样本是分析证据，不是额外用户指令，也不要求复制其地点、路线、角色职能或具体笑点。

### B 的创作顺序：先设计完整经历，再分配地点

B 不是把一个场所套成传统戏剧的“起承转合”，也不是把若干地点排成旅游清单。先回答“这一天／这段经历具体经历了什么”，再回答“每一段由什么地点承载”。大纲阶段必须先写一条**体验主线／活动链**，用行为动词串起入口、移动或会合、主要活动、活动后的变化／恢复和结束；地点只能作为这些阶段的承载物。

**主题串起整段经历。** 对短途出游而言，主要任务只是其中一个核心模块，饭后或任务完成后必须继续出现一个有独立观看承诺的**后续独立活动或状态**，除非主题本身明确就是单项任务。比如“坐火车去隔壁城市吃早茶”的主题是完成一次短途城市旅行；早茶是上午的主要任务和第一次满足，不能承包整条视频。

- 先选择本集的结构变体和**新鲜感发动机**，再决定地点。出游题材可以包含一个很长的生活任务模块；只有当一项日常任务本身就是本集完整经历时，才使用 `生活任务` 变体，不因“有一个中心地点”自动归类。
- 核心模块代表一段完整活动／经历（会合、移动、进入活动、完成活动、饭后／活动后、返程等），不是把点餐、等待、吃饭、结账、揭盖、处理同一物件或同一设施的重复操作逐项升级成宏观剧情。后者应作为模块内部的连续故事段或真实切镜；只有**任务／对象／时间／关系／环境或能量真正变化**时才升格为新的核心模块。
- **同一物理空间可以成立**，可以承载多个连续故事段，甚至多个核心模块；判断是否成立要看**活动家族和任务接力**，不看地点数量或人为比例。若 Hook、早期回报、主任务、核心记忆和 Recovery 都只是同一项任务的微步骤，先合并为一个核心模块或退回重写体验主线；若地点不变但搭营→餐食→抓鱼→玩水→夜间活动等任务、时段、身体／关系状态和能量确实换挡，则可以保留。
- 单地点也不得把局部动作硬写成传统冲突—升级—高潮。起伏必须来自任务接力、时间推进、环境／设施状态、关系反应或身体需要；没有新的外部状态变化时，合并微任务或结束该模块。这里是结构诊断，不是“必须换几个地点”的硬阈值。

这条顺序不等于强制频繁换景：户外或日常题材可以在同一空间推进多个任务；但必须先证明“经历链”本身成立，再决定是否保留同一空间，而不是从一个地点反推整集剧情。

**样本校准门：**动笔写正文前，先读取 `references/b-vlog-scene-architecture.md`，并以完整分析和原始逐切镜为证据完成一张“结构变体／新鲜感发动机／核心模块链／每模块预计时长／模块完成与下一场触发”的校准表。不得先看问题稿的表面地点或起承转合标签，再反推 B 规则；样本表是容量和连接方式的参考，不是复制清单或硬配额。

### 主题节奏门：主题先出现，高潮后兑现

干嘛猫的“主题”不是“主高潮”或“最长任务”。写大纲时必须把以下四个时间点分开记录：

1. **主题承诺首现（Hook）**：观众第一次看见本集要看的对象、关系、目标或环境问题；冷开场可以直接给核心活动的片段，普通日常可以从起床／第一项生活动作建立“今天的一天”。
2. **主题场域建立（Establish）**：画面第一次明确回答“今天要干什么”，例如水族馆大环境、溪流、漂流艇、团建队伍或第一项日常任务。
3. **第一次主题兑现（First Payoff）**：主题相关的第一项实际任务或小回报已经发生，而不是只靠标题、台词或“等会儿去”承诺。
4. **核心记忆事件（Core Event）**：本集最值得记住的动作、喜剧、完成、关系或情绪时刻；它可以在中后段才正式展开，不能倒推成主题首次出现时间。

五条样本的共同节奏是：主题承诺通常在 `0:00—0:15` 出现，普通出游在约 `0:15—0:35` 完成主题场域建立（样本最晚约 `0:30.60`），并在前 `0:30—0:45` 给出第一项主题动作或小回报；冷开场样本可以在 `0:00—0:06` 先展示主题，再回到起点。核心记忆事件则可后置到成片约 `51%—79%`。这两个时间范围不能互换。

**主题延迟退回条件：**

- 前 `0:15` 仍只有泛化起床、穿戴、集合或交通，没有主题对象、主题关系、目标或可辨识环境信号；
- 普通单日／旅行题材到约 `0:30—0:35` 仍未建立主题场域，或到前 `0:45` 仍没有第一项主题动作／小回报；
- 直到 `1:00` 左右才第一次出现真正主题，却把此前内容写成必需铺垫；
- 只在 Hook 闪现一次主题，随后长时间消失，直到核心高潮才重新出现；
- 把“核心事件在 51%—79%”误写成“主题在 51%—79% 才出现”；
- 单项主题（例如“今天去健身”“今天吃早茶”）直到后半段才开始执行：要么前置可识别的目标和第一动作，要么把主题改写成覆盖整天的更大经历。

**主题节奏表必须写入大纲：**`主题承诺句（umbrella 主题）`、`子主题／主任务`、`主题承诺首现时间／镜头`、`主题场域建立时间／镜头`、`第一次主题兑现时间／镜头`、`核心记忆事件时间／镜头`、`两者之间的任务链`。主题场域可由目的地、活动对象、群体关系或第一项动作建立，不要求一秒到达目的地，但不能让泛化准备承包前一分钟。

一日故事同时推进三条嵌套曲线：

| 曲线 | 基本走向 | 必须留下的可见证据 |
|---|---|---|
| 时间曲线 | 早晨 → 白天 → 午后 → 黄昏 → 夜晚 | 光线、环境、装备、活动时段或明确的跨日信号确实改变 |
| 任务曲线 | 目标出现 → 准备 → 执行 → 变化／Reaction → 完成 → 休息／转场 | 每个重要任务为何开始、怎样做完、做完后留下什么状态 |
| 关系曲线 | 独处／分散 → 会合 → 共同经历 → 集体记忆 → 告别 | 成员进入、互相影响、共同结果和最后的关系停点 |

单日／跨日故事按三条曲线验收。非日程型完整经历不强行补“早晨→夜晚”，而是记录适用的曲线（通常是任务、关系、能量／余波）以及“不适用及替代证据”；单人经历可以把关系曲线替换为自我状态或身体恢复曲线。任何省略都必须说明它如何仍然证明经历开始、变化和结束。

常见波形是：

> 低位基线 → 第一次上升 → 早期小回报 → 回落／呼吸 → 第二次上升 → 中段笑点或小事件 → 再次回落 → 中后段核心记忆事件 → 后果与恢复 → 夜晚结束仪式

这是功能地图，不是固定八拍模板；出发、主题建立、首次提速和主高潮可以合并、省略或由其他功能承担，但省略必须说明原因。每集要指定一个最能代表本次经历的 **核心记忆事件**，类型可以是动作、喜剧、完成、关系或情绪，不要求一定是危险动作，也不要求成为最长段落。核心事件前应有一次小回报，核心事件后必须保留后果、恢复、继续体验或安静余波，最后用 `Ending Ceremony` 让观众明确感到这段经历结束。

`Entry / Hook` 可以是低能量生活基线、高潮冷开场或成员入场快剪；若先给高潮，必须尽快补回“这一天从哪里开始”的时间和关系基线，不能让观众只看到刺激而看不懂完整经历。

故事能量和剪辑节奏分开规划：能量由强度、新鲜度、风险／难度、参与人数、完成临近度和情绪浓度决定；剪辑节奏由镜头时长、切镜频率、动作拆分和信息密度决定。高能量可以用较长广角镜头保留现场，低烈度也可以用快 Reaction 交代群体；不能把“快切”当成高潮的唯一证明，也不能机械把高潮写得最长。

**故事起伏不等于剪辑快慢。** 过程任务可以占据最长篇幅来证明“真的做过”，核心记忆事件负责瞬间兑现；不能因为高潮最刺激就自动把它写成全片最长段落。

也就是说，**故事能量不等于剪辑速度**；两者必须分别记录和验收。

B 的六类功能单元可作为矩阵标签：`Entry / 生活基线`、`Threshold / 出发与会合`、`Task / 过程任务`、`Payoff / 高点与核心记忆`、`Recovery / 回落与余波`、`Ending Ceremony / 结束仪式`。这是功能分类，不是必须各占一个地点或固定秒数。

在进入逐镜前先完成三层拆解：

> **核心模块 → 连续故事段 → 真实切镜**

1. **核心场景—事件模块（大纲层）**：一次完整经历或任务包；场景不是纯物理地点，而是 `地点语义 + 当前任务 + 角色状态 + 能量功能`。
2. **连续故事段（场景编排层）**：模块内部因任务、时段、地点、参与关系或能量功能改变而形成的连续段。
3. **真实切镜（Storyboard 层）**：一次真实剪辑切镜一行；再由每个切镜派生首帧和绑定视频提示词。

每个核心模块在矩阵中至少写清：进入状态、任务／目标、关键过程、变化／Reaction、完成结果或持续状态、下一场触发原因、连接类型和能量功能。**七类有效切场动因**是：任务完成、结果产生因果后续、身体／生活需要改变、时间门槛、关系状态改变、当前对象新鲜度耗尽、需要改变能量方向。每次切场都要回答“上一场完成了什么，或它制造了下一场为什么必须发生的原因”。任务之间至少用因果、时间或关系连接；重要转折优先同时具备两种。

B 样本的约 `2:15–2:35`、`8–11` 个核心模块、`11–25` 个连续故事段和 `46–67` 个实际切镜只作为**参考容量**。它们不能变成所有 Vlog 的硬配额，也不能把连续故事段误当成换地点次数。五条样本的密度校准还显示：核心事件模块平均约 `15秒` 切换一次，普通连续故事段平均约 `8.5秒`、中位数约 `6.1秒`；普通模块多在 `10—25秒`，重过程模块可到 `34—45秒`，但必须持续更换任务、对象、动作、时段、关系或身体／能量状态。单一任务在同一语义区域连续超过 `45秒` 需红队复核，超过 `60秒`（例如把一顿早茶写成约 `70秒`）默认退回重做体验主线；不能把揭盖、点餐、等待、处理菜品、吃饭和结账等微步骤用 `Hook／回报／高潮／恢复` 标签伪装成多个宏观模块。普通连续故事段若超过 `15—20秒`，必须写明连续动作的观看价值和内部状态变化；否则合并、切换任务或补独立后续活动。跨日旅行在 `Day Boundary / Reset` 处清零并重建下一天的时间、身体、装备、关系和任务目标；非日程型完整经历沿用任务、关系、余波和结束仪式逻辑，但不强行补早晚。

场景密度取决于新鲜感从哪里来：观光型可以换对象，群像型可以换活动与 Reaction，日常型可以把过程拍细，户外型可以在同一空间推进连续任务，冒险型可以依靠风险升级与后果；不要拿某一变体的段数套用另一种故事。

## 渐进式创作协议

本 skill 默认是**分阶段、需确认、不可跳步**的创作流程，不是把一句选题直接转换成视频提示词，也不是在一次回复中把主题、大纲、角色、Storyboard 和下游提示词按章节全部写完。

**铁律：上游阶段的当前阶段由“最早一个尚未冻结的必需产物”决定。每轮只打磨这个产物；用户明确确认后，才解锁下一阶段。** 对干嘛猫／B 风格 VLOG，主题、大纲和 Storyboard 的冻结逻辑保留；Storyboard 冻结后，默认主链不再是“生图资产／Seedance 并列”，而是每个真实切镜逐一建立首帧，再逐一建立绑定该首帧的视频提示词。**台词表唯一写入者是 `writing-snail-vlog-subtitles`；本 skill 不编写台词格，只核对并交接其冻结输入。** 旧的按组 Seedance 和稀疏生图资产仍可作为明确点名的兼容分支，但不能替代 B 模式主链。每轮只处理一个正式产物；可以说明下一阶段将做什么，但不能附带其他阶段或分支的完整草稿、预览或示例成品。

### 阶段顺序

1. **主题讨论 → 主题冻结**：比较少量可行的生活愿望与主题方向，并为推荐主题明确列出 **2—3 个彼此不同、可在画面中兑现的观看承诺**、至少一个只因蜗牛身体或环境关系才成立的不可替代点，以及与三条最新脚本在地点、路线、对象、因果或笑点落点上的具体差异。定稿时只冻结一句话生活愿望、这些主题承诺、蜗牛不可替代点、故事范围和排除方向；不预先冻结完整因果、高潮或结尾，也不写完整故事大纲、角色任务、逐镜或视频提示词。
2. **故事大纲 → 大纲冻结**：围绕已定主题把故事从开场到结尾讲完整。B／干嘛猫模式先完成“样本校准表、体验主线／活动链、核心模块链与每模块时长预算”，再完成“一日故事曲线”和“核心场景—事件矩阵”，最后用故事语言写活动吸引力、任务小弧线、升级／核心记忆事件、可见结果、后果与恢复和 `Ending Ceremony`；通用模式仍按活动需要组织。大纲不能退化成地点或日程列表，也不能把同一任务的微步骤拆成多个宏观模块：每个重要任务至少写清目标 → 准备／过程 → 变化或 Reaction → 完成；每个段落必须完成上一件事或制造下一件事的触发；每个模块都要写预计成片时长及其依据。大纲不写焦段、机位或模型指令；故事弧和亮点没有确认，不进入角色分配。
3. **角色情节设计 → 角色稿冻结**：在大纲成立后，先读取可用的跨集行为依据，再逐桥段和逐角色检视为什么在场、当下目标、主动选择、触发、动作、反应、朋友关系和持续后果。每个跨集倾向都要注明过去已冻结行为的地址／修订、本集是延续还是变化／反例，以及最近应避免机械重复的动作；没有证据就只写本集选择，不把单次行为升级成永久性格。反复打磨到每个保留角色都有自然的情节轨，而不是固定职业任务或平均分配的露脸指标；角色设计若改变故事因果或亮点，退回大纲重新确认。
4. **Storyboard（逐镜视觉脚本）→ Storyboard 冻结**：只把已经确认的故事和角色情节拆成真实剪辑点，设计场景、摄影机、正式角色、动作链、接触因果、状态转换、声音和收口。每次真实剪辑切镜就是一个 Storyboard 镜头；空镜、Reaction、重复机位、黑场按真实切镜保留，同一连续镜头内的遮挡或快速运动不凭感觉另拆。冻结时必须锁定全片连续镜头号 `镜头001、镜头002……`，每个大纲桥段至少有一个兑现镜头，每个镜头只出现一次且不隐藏第二个构图。Storyboard 不写视频模型直投语言，也不靠台词格补足画面事实。
5. **B 模式逐镜首帧提示词**：Storyboard 冻结后，**每个真实镜头一个首帧**，逐镜输出一条完整、独立、可直接抽卡的首帧提示词。首帧提示词是逐镜必需产物，不是可选资产；不能用 A-FRAME 是否需要来替代。按镜头功能选择 `Action Start`、`Payoff State`、`Ongoing Motion State` 或 `Stable State`，并在同一条提示词中重建角色 Anchor、首帧状态、道具关系、摄影机关系和环境可信度。首帧尚未生成、选择或验证时，不进入该镜的视频提示词。
6. **B 模式首帧验证 → 基于首帧的逐镜视频提示词**：先生成／选择同镜首帧并记录版本、文件地址和验证状态；只有首帧已选且已验证，才为该镜写基于首帧的逐镜视频提示词。视频提示词必须引用 `来源首帧`，只描述从该静态起点开始的一个主要动作（起点 → 过程 → 收口），可指定 Motion Carrier、摄影机运动、不可改变的 Anchor、建议 4–6 秒生成时长和成片裁剪区间。**视频提示词不得脱离首帧重新设计构图、角色、道具、摄影机或第二个镜头**，不得写“承接上一镜最后一帧”、对白、口型或自动字幕；首帧错误先回退首帧修订，不用视频提示词修静态身份。
7. **逐镜视频生成与验收**：按每镜视频提示词生成 4–6 秒素材，逐镜检查角色身份、主动作、道具关系、方向、入／出点和语义连续性，再从稳定区间裁成片。生成时长与最终剪辑镜长分开；视频结果有偏差时先判断是首帧、视频措辞还是上游 Storyboard 的问题，再按失效矩阵回流。
8. **其他制作交付（显式兼容分支）**：台词表、生图资产清单和旧式按组 Seedance 只在用户明确点名时进入；它们必须引用已冻结 Storyboard 和 B 模式产物，不能把组级一次提交当作默认创作单位。
   - **台词分镜组别对应表交接**：核对冻结 Storyboard、时间戳、画面／动作／声音事实和冻结角色情节后，调用 `writing-snail-vlog-subtitles`。该 skill 独立输出五列表；本 skill 不起草候选台词。
   - **可选生图资产清单与提示词**：只为确有复用价值的角色变体、场景板、关键道具或特效建立资产 ID。B 模式逐镜首帧不归入稀疏资产清单；首帧状态、版本和文件地址写入逐镜首帧产物。详细字段使用 `references/asset-prep-template.md`。
   - **可选旧式 Seedance 组转换**：仅在用户明确要求“一组一次提交”或已有平台约束时，把已锁定镜头按组转换；它必须声明来源 Storyboard、逐镜首帧／视频提示词映射和资产依赖，不能取代逐镜首帧→逐镜视频主链。

主流程因此是：

> 主题讨论并冻结 → 故事大纲讨论并冻结 → 角色情节讨论并冻结 → Storyboard 讨论并冻结 → 逐镜首帧提示词 → 首帧生成／选择／验证 → 基于首帧的逐镜视频提示词 → 4–6 秒视频生成／逐镜验收／成片裁剪

台词交接和旧式组级 Seedance 是上述主链之外的兼容分支；它们不能把“每镜一个首帧、每镜一个视频提示词”的一一绑定关系改成可选项。

### 脚本地址、修订与来源

主题、大纲、角色情节、Storyboard、逐镜首帧提示词和逐镜视频提示词，以及任何兼容分支，都必须绑定同一条独立脚本地址。每轮先读取该地址内现有的 `脚本状态.md`、当前产物和来源产物；地址不存在或用户尚未指定时，标记 `待确认`，不得把聊天标题、旧文件名或相邻脚本目录猜成正式地址。所有正式产物统一使用 `references/production-versioning.md` 的“权威产物头部”，其他模板不得定义不同字段集。

每份产物开头必须原样包含以下权威字段；下游可增加来源逐镜、覆盖镜头或分组依据，但不能删除或改名：

```markdown
- 所属脚本：[独立脚本地址]
- 产物：[主题／故事大纲／角色情节／Storyboard／逐镜首帧提示词／逐镜视频提示词／台词分镜组别对应表／兼容生图资产清单与提示词／兼容 Seedance第__组]
- 当前修订：[修订001 起，各产物独立递增]
- 来源：[上游产物地址与修订；主题写用户输入／参考材料]
- 状态：[讨论中／待确认／已冻结／已失效／已取代]
- 创建日期：[YYYY-MM-DD]
- 用户确认：[原话摘要／无]
- 取代／失效依据：[无，或新修订及上游变化]
```

用户确认后的文件不覆盖；修改时新建该产物的下一修订。新修订仍在讨论或待确认时，旧冻结稿保留为上一条完整基线，但本轮不得把新旧来源混用；只有新修订被用户确认后，才把旧冻结修订标为 `已取代`，并按失效矩阵处理下游。上游新修订已冻结而下游尚未重新验收时，下游标为 `已失效`，不能作为继续创作或转换的基线。`待确认`稿内容未变化时不得仅为再次展示而新建修订。旧文件名中的 `V1.x` 只按原样保留为输入材料，不能据此推断当前修订、冻结状态或来源关系。

| 故事大纲因果、桥段、高潮、结果或收束 | 角色情节、Storyboard、逐镜首帧提示词、逐镜视频提示词、台词分镜组别对应表、兼容生图资产清单与提示词、全部兼容 Seedance 组 |
| 角色情节的在场角色、选择、动作或关系反应 | Storyboard、逐镜首帧提示词、逐镜视频提示词、台词分镜组别对应表、兼容生图资产清单与提示词、全部兼容 Seedance 组、引用这些来源的角色连续性证据 |
| 逐镜画面事实、全片镜头号 | 逐镜首帧提示词、逐镜视频提示词、台词分镜组别对应表、生图资产清单与提示词、全部 Seedance 组、引用该逐镜的角色连续性证据 |
| Storyboard 的切镜边界、镜头号或镜头状态变化 | 该镜及受影响镜头的首帧提示词、视频提示词、台词表、生图资产清单与全部 Seedance 组失效；新建 Storyboard 修订后重新逐镜派生 |
| 只改首帧提示词、首帧版本或首帧图片且 Storyboard 事实不变 | 该镜的首帧提示词新建修订；绑定该镜的视频提示词和视频结果标记 `已失效`／`待重验`，不能继续引用旧首帧 |
| 只改逐镜视频提示词且首帧与 Storyboard 不变 | 只新建对应镜头的视频提示词修订；该镜已有视频结果标记 `待重验`，首帧和台词表不失效 |

### 入口判定：已有稿件接续（不计入创作阶段）

如果用户提供了某个既有版本、旧稿、分镜文件、台词分镜表或 Seedance 草稿，这不是新增的“版本参考阶段”，也不自动把流程推进到该文件的标题所暗示的阶段。先做一次入口判定：

1. 记录文件地址、文件自称修订和可核实来源，不用文件名猜当前有效版本；
2. 判断文件实际包含主题、故事大纲、角色情节、Storyboard、逐镜首帧提示词、逐镜视频提示词、台词分镜组别对应表和／或兼容 Seedance 转换中的哪些产物；
3. 分别判断每一层是否内容完整、是否有用户明确批准、其上游来源是否仍有效；
4. 当前创作阶段取最早一个尚未冻结或已经失效的必需产物，再从那里继续。

三种用户意图要分开处理：

- **“参考这份稿件”**：只把它当分析材料，不能冻结任何层；先报告它能提供什么、缺什么。
- **“按这份稿件继续”**：把它当接续基线，但仍逐层验收；只承认文件中实际存在且用户已确认的层级。
- **“按这份稿件定稿”**：可冻结文件中实际存在且通过完整性检查的连续上游层级，但不能冻结文件中不存在的角色稿、分镜稿或台词分镜组别对应表。

因此，“参考某个版本”描述的是**输入方式**，不是主题、大纲、角色、分镜或 Seedance 中的任何一个创作阶段。

### 阶段门槛

- **确认按对话语境判断**：用户明确说“就这个”“按这版继续”“定稿”“进入下一步”，或在你刚请求当前阶段确认后回复“可以／继续”，可视为批准当前阶段。单独的“继续任务”如果只是恢复中断工作，只恢复当前阶段，不自动冻结内容。
- **批准只冻结当前产物**：确认主题不等于批准尚未写出的故事；确认大纲不等于默认接受角色分配；确认分镜前的任何“可以”都不能被解释为允许直接出提示词。
- **一轮只推进一个阶段**：当前阶段交付末尾请求确认并停止。即使下游答案看似显而易见，也不能同轮附送大纲、角色表、逐镜或 Seedance 草稿。这里的“最小必要交付”是当前阶段的一份可讨论完整稿，不是下一阶段的开头。只有用户明确要求审查一套已经存在的完整产物时，才可在一轮中做跨层缺口审计，但仍从最早缺口开始修改。
- **允许从中间阶段接续，但要逐层验收**：用户可以直接提供已确认主题、已锁定大纲、指定版本稿或完整逐镜稿。版本名或“按这版”不是跳过所有阶段的通行证；逐项检查该稿件是否真的写清并冻结主题、大纲亮点、角色情节和视觉镜头，只承认实际存在且符合门槛的层级，从最早缺失或冲突处继续。
- **参考不等于批准**：若用户只是提供文件、草稿、参考案例或说“可以参考”，先审查缺口，不能自动把它当成定稿，更不能因它看起来接近提示词格式就默认故事已完成。
- **改变上游决策要回退并传播失效**：主题、核心因果、高潮、角色情节、Storyboard 镜头号或兼容组别映射一旦改变，先按上游失效矩阵更新所有受影响产物，再回到受影响的最早阶段；不能只改下游文字让旧来源偷偷适配。
- **阶段交付要有状态头**：每次输出开头先写所属脚本地址、产物、当前修订、来源、状态和取代／失效依据，再标记是否已读取 `reference-mechanics.md` 与 `ganamao-six-script-deconstruction.md`，并逐项写主题、大纲、角色情节、Storyboard、首帧和视频提示词的状态。还要写本轮待确认问题和不处理的下游内容。兼容 Seedance 最终净输入块不能含“讨论中”“待确认”、备选方案或占位符。
- **用户直接要求跳到提示词时**：先检查上游是否有已确认主题、大纲、角色情节和 Storyboard；缺哪一层就返回哪一层的最小必要交付。Storyboard 已冻结但同镜首帧未选／未验证时，只交首帧提示词或首帧缺口，不直接生成视频提示词。

### B 主链与兼容分支的交接

`developing-snail-vlogs` 负责主题、故事、角色情节、Storyboard、逐镜首帧提示词、逐镜视频提示词、资产准备和兼容 Seedance 适配，并为台词分镜组别对应表提供冻结画面事实。`writing-snail-vlog-subtitles` 是台词表唯一写入者。B 模式的首帧表与视频提示词表是一一绑定的主链；可选资产和旧式 Seedance 只能引用这条主链，不能替代它，也不能复制对方的整段提示词。任何下游都不能替代大纲、角色情节或 Storyboard，不能绕过首帧验证门。

- 需要整理逐镜首帧提示词或首帧验证：读取 `references/templates.md` 的“Storyboard、逐镜首帧提示词与首帧验证模板”和 `references/production-versioning.md`；首帧不是可选的 `A-FRAME` 资产。
- 需要整理逐镜视频提示词、视频生成或结果验收：读取 `references/templates.md` 的“基于首帧的逐镜视频提示词模板”和 `references/seedance-validation-checklist.md`（该清单的 B 模式部分）；必须绑定同镜已验证首帧。
- 需要整理逐镜预生成图片、资产复用或兼容生图资产提示词：读取 `references/asset-prep-template.md`，并同时读取 `references/production-versioning.md`。**只有用户明确要求旧式 Seedance 组兼容分支时**，即使只说“给视频提示词”，也先判断逐组图片依赖；发现必须资产缺口时，本轮只交付“生图资产清单与提示词”并停止。B 模式逐镜视频提示词不经过这条资产门，只受同镜首帧已选且已验证门约束。
- 主题、大纲、角色情节和 Storyboard 均已明确冻结、且用户明确要求旧式一组一次提交的 Seedance 直投提示词：读取 `references/templates.md` 的“Seedance 直投提示词模板”和 `references/seedance-validation-checklist.md`。
- 审查现有草稿、诊断“刻意／没意思”或核对失败模式：读取 `references/approved-example.md`。开发全新主题时，先独立完成桥段池和故事骨架，再决定是否读取；不得把案例当选题库。

打包原文来自 `I:/干嘛猫脚本分析.md`。来源完整性检查先核对三条详细时间轴标题和 49／29／38 行数，再比较两个 skill 副本的行数与哈希；副本不一致时记录路径、行数、哈希和缺失范围，不自动覆盖权威源。若源文件、提炼版与用户最新决定冲突，指出差异并以用户最新指令为准。

## 工作流

以下章节是各阶段的方法库，**不是要求在同一轮从 1 执行到最后的清单**：主题阶段只执行 1—2；主题冻结后执行 3—4（B 模式在此完成故事弧和场景—事件矩阵）；大纲冻结后执行 5；角色稿冻结后执行 6；Storyboard 冻结后按 7→8→9→10 逐镜推进。兼容资产和旧式 Seedance 只在用户明确点名时进入 11—12，不能插入首帧验证之前，也不能替代 B 模式主链。到达当前阶段退出条件后必须停下等待确认。

### 1. 锁定生活愿望

把本集压缩成一句普通人会说的话：

> 今天想和朋友去／做______。

要求这件事即使换成人类朋友也值得拍成 VLOG。优先选择期待、放松、庆祝、解压、季节感、共同体验等生活动机。不要从角色的职业、能力、名字、外形梗或资产库存出发。

如果活动本身没有观看价值，停止并重选；不要用悬念、台词或世界观掩盖空洞题材。

开始主题讨论前，先用 `reference-mechanics.md` 和 `ganamao-six-script-deconstruction.md` 校验：这项活动是否像三条最新脚本那样具有普通人愿意参加的观看价值、多个视觉动作、自然的环境／设施变化、高潮闭合，以及恢复、关系反应或安静余波空间。推荐主题必须把观看价值拆成 2—3 个不同的可见观看承诺；“好玩、治愈、有反差”之类抽象形容不算承诺，必须写明观众将看到什么动作、变化或结果。参考干嘛猫的是结构机制，不是把新故事套进旧路线。

### 2. 选择真实活动

先在内部比较 2—3 个主题方向：

- 活动本身是否令人向往；
- 是否包含多个明确的动作动词；
- 场地、天气、物体或身体是否会自然制造变化；
- 是否能形成可见结果或状态变化；
- 是否能形成高能与处理、继续体验或安静余波的起伏。

只保留最强方向。用户要求一个方案时，只展开推荐项，不把内部备选倾倒给用户；但推荐项自身仍必须对外列出 2—3 个不同的可见观看承诺，不能把“内部比较过 2—3 个方向”当作替代。

每个观看承诺在主题内部都必须通过同一最小合同：`主动动作 → 环境／物体／身体变化 → 可见结果／收口`。主题阶段只验证局部事件潜力，不提前写完整故事；不同地点或不同对象不算不同机制。至少两个承诺必须在动作、变化来源或结果上真正不同，不能把“看牌坊、看河景、看展馆”包装成三个承诺。

主题冻结前再补齐两项硬证据：

- **蜗牛不可替代点**：至少一处关键观看承诺自然依赖移动速度、壳的体积与形状、黏滑痕迹、触角视线、湿润需求或蜗牛与真实场地的尺度关系。删除蜗牛特性后活动仍应值得人类参加，但至少一个传播画面或桥段机制会因此明显失去成立理由；只把人类动作换成蜗牛外形不合格。
- **三条脚本具体差异**：分别写清与海洋馆、山水漂流、周末聚会／游乐园样本在地点、路线、活动对象、环境发动机、核心因果和笑点落点上的差异。只写“不是换皮”“地点不同”不合格。
- **历史机制差异**：对照 `vlogs/脚本总表.md` 已登记的冻结故事，写清本次与最近脚本在活动、环境发动机、核心因果、高潮机制、可见结果和关系变化上的差异。若明确做回调，必须说明改变了哪一项和为什么值得再次使用。

在此阶段不要借用已通过案例的具体因果链。更换地点、天气或道具，但保留同样的追赶方式、三次事故、被保护物品与结局，仍属于换皮。

### 3. 暂时隐藏角色姓名

在选角前，为活动列出至少 10 个可视动作或小意外。优先使用骑、挤、滑、追、吹、撞、抓、漂、翻、泼、抬、躲等动词。

短桥段优先在 1—3 个镜头内局部闭环；连续高潮可以跨更多镜头，但每个子动作仍要读得清楚。事件型候选包含：

1. 一个清楚动作；
2. 一个来自环境、物体、身体或群体互动的变化；
3. 一个无需解释即可理解的反应或后果。

删除只靠站立、聊天、解释性画面文字、背景知识或角色设定成立的桥段。

### 4. 建立体验曲线与 B 故事架构

通用蜗牛 Vlog 仍可从候选桥段中选择 5—7 个最强桥段，组织“进入活动 → 活动证明 → 局部变化／升级 → 结果 → 处理或余波 → 结束”。

若制作模式为 B／干嘛猫，先不要直接列镜头或机械凑地点，按以下顺序组织：

0. 先读取 `references/b-vlog-scene-architecture.md` 和用户提供的完整分析／原始逐切镜，完成样本校准：写出本集结构变体、新鲜感发动机、对照样本机制、核心模块链、每模块预计成片时长、模块完成状态和下一场触发。没有这张表，不进入正文，也不能从当前问题稿反推规则。
1. 先写**主题节奏表**，区分 `主题承诺首现`、`主题场域建立`、`第一次主题兑现` 和 `核心记忆事件` 四个时间点；普通出游／日常应在前 `15—30秒` 建立主题场域，前 `30—45秒` 出现第一项主题动作或小回报，冷开场可在前 `0—6秒` 先给主题再回到起点。核心记忆事件可以后置，但不能用后置高潮掩盖主题延迟。若主题是单项任务，前 `15—30秒` 必须出现可辨识目标或第一动作，否则退回主题讨论并扩大主题范围。
2. 先写**体验主线／活动链**，列出本次经历的活动阶段、每阶段的动作对象、状态变化和下一阶段触发；先不写地点名。出游／旅行题材至少要能读出“进入／移动 → 主要活动 → 活动后状态或另一项自然活动 → 返回／结束”，不把交通只当片头片尾。
3. 再把活动阶段归并为 `核心场景—事件模块`，并为每个模块选择地点语义；随后拆成 `连续故事段`，最后才交给 Storyboard 拆成真实切镜。容量区间只作参考，不是硬配额。对每个模块同时填写预计时长和“是否发生结构性换挡”；单一任务连续超过 `45秒` 必须解释，超过 `60秒` 默认退回。
4. 画出时间、任务、关系三条曲线，并标出基线、至少一次上升与主动回落、再次上升、核心记忆事件、后果／恢复和结束仪式；若是非日程完整经历或单人故事，记录适用曲线及替代证据，不得为了填表虚构夜晚或同行关系。
5. 给核心记忆事件指定类型（动作／喜剧／完成／关系／情绪）和前置积累；它可以短于承担过程的任务，但不能没有可见兑现或余波。
6. 对每个重要任务填写 `目标 → 准备／过程 → 变化／Reaction → 完成`；不要求每个节点独立成镜，但观众必须看懂为何开始、怎样完成、完成后怎样。把同一场所内的微动作归入其所属活动阶段，不得用菜品／道具清单代替活动链。
7. 在主事件前安排一次早期小回报；每个回落段至少承担收尾、恢复、转场、推进时间或加深关系中的一项；核心事件后不能直接黑场。
8. 为每次切场注明任务完成、因果后续、身体／生活需要、时间门槛、关系变化、新鲜度耗尽或能量转向中的至少一种触发。

允许一个环境变化递进三次，但不要把每集都写成传统任务、案件或反转故事。让观众比角色早半拍发现变化，会比角色解释变化更自然。

### 5. 最后放入角色

默认让 Garden 承担体验锚点或掌镜视角。只选择活动真正需要的朋友，并遵守 `references/cast-policy.md`。

分配本集情节前，先列每个候选角色的跨集行为依据：`来源脚本地址／冻结角色情节修订／过去可见选择或关系动作／本集延续、变化或反例／最近避免重复的动作`。只使用已冻结稿；讨论稿、外形、职业、口癖和一次偶然动作不能单独成为跨集依据。若没有可核实记录，写“无跨集依据”，本集只按现场行为成立。

把提示中“可用、备选、希望尽量露脸”理解为角色池，不是强制清单。只有用户明确说“本集必须出现”时才视为硬约束；即使如此，也优先让多余角色作为普通同行者共同在场，而非新增职责。

- 不平均分配时长、台词或笑点；
- 不要求固定阵容全部出场；
- 每个局部桥段优先只设一个动作中心；
- 根据距离、构图和当下行为分配动作，不根据名字强配职责；
- 让差异通过抢先、犹豫、跟随、补救、护住物品等选择自然泄露；
- 不让角色通过职业动作、标志物或台词证明“我是谁”。

把限定角色和彩蛋放在剧本完成后的装饰层。删除它们后，主线必须完全成立。

不得为了宝箱吸血鬼蜗而把原本完整的白天行程拖到夜晚，也不得在写生活愿望时预先添加“待到天黑”。先在没有限定角色和彩蛋的情况下确定自然结束时间；只有活动本身本来就会持续到夜间，才考虑夜间限定角色。

### 6. 写成可拍脚本

时长按制作模式决定：B／干嘛猫模式可将约 2:15—2:35、约 8—11 个核心模块、约 11—25 个连续故事段和约 46—67 个实际切镜作为样本复刻参考；通用蜗牛模式默认控制在 90—120 秒。用户指定优先，任何区间都不是硬配额：

- 让多数信息节拍持续约 2—4 秒；
- 允许表演、狼狈过程、情绪停顿或收尾画面持续 5—10 秒；
- 按动作与信息决定时长，不机械快切；
- 只把已确认的大纲和角色情节转换成画面，不在分镜阶段新增桥段、改变高潮或重新分配角色任务；
- 画面独立交代“发生了什么”，每个事件型关键动作都有起因、过程、反应和可见结果；纯呼吸、满足或景色段可以由状态和感官价值成立；
- 同一事件下让朋友作出不同方向的可见判断，不把“普通朋友”写成无差异群像，也不让所有人轮流表演；
- 保持关键物品、身体状态和环境变化的前后连续；
- 高能之后安排题材适配的处理、关系反应、继续体验或安静余波，不在未闭合的意外瞬间结束；
- B 模式逐镜前先绑定来源核心模块、连续故事段、故事功能、进入／退出状态和下一场触发；不能在 Storyboard 阶段新增故事弧或把故事能量误写成剪辑速度；
- 停在体验余味上，不总结友情、成长或人生道理。

Storyboard 先独立完成并冻结。冻结前建立 `大纲桥段 → 兑现镜头001……` 和全片连续镜头号；每次真实剪辑切镜一行，空镜、Reaction、重复机位和黑场按真实剪辑保留，同一连续镜头内的遮挡／水花／快速运动不凭感觉另拆。兼容 Seedance 的 `全片镜头 → 组别 → 组内镜头` 映射只有在用户明确采用组级一次提交时才建立，不能作为 B 模式首帧或视频提示词的前置门。没有兑现镜头、镜头边界不清或动作因果不完整，都不能冻结。Storyboard 可以标记台词机会，但不能借台词改写动作或补充缺失因果；具体台词只在独立交接中填写。

不要机械复制参考作品的水族馆、漂流、烘干机、过山车、烟花等具体组合；只迁移其体验机制。

### 7. 后置制作适配与 B 模式生产边界

只在故事大纲和角色情节通过后评估现有动画、后期难度和成本。把方案拆成：

- 不可丢失的桥段机制；
- 可替换的地点、道具、机位、动作实现和剪辑方式。

缺少现成动作时，先寻找不损害“动作—变化—结果”的实现方式。不得在创意阶段因为动作少而把成立的笑点降级为静态站立加屏幕文字。

Storyboard 冻结后，B 模式的生产单位变成“一个真实镜头一对首帧／视频提示词”，不是 Seedance 组。先建立全片镜头清单，再逐镜完成首帧和验证；视频提示词不得抢先写，也不得以组级首帧或上一镜结果代替同镜首帧。

### 8. 逐镜生成首帧提示词

读取 `references/b-vlog-final-analysis.md`、`references/b-vlog-shot-prompt-examples.md`、`references/b-vlog-five-column-examples.md` 和 `references/templates.md`。附件中的五列表是证据参考：一次真实剪辑切镜一行，末列是独立首帧图像提示词，不是视频提示词。正式产物仍须使用权威状态头。

每个 Storyboard 镜头恰好建立一条首帧提示词，至少包含：

- `镜头编号、Storyboard 来源桥段、时间／章节、镜头摘要`；
- 首帧类型四选一：`Action Start`、`Payoff State`、`Ongoing Motion State`、`Stable State`；
- 角色 Anchor（毛色、体型、帽子／配件等身份不变量）；
- 首帧静态状态、关键道具的归属和空间关系；
- 成片摄影机位置／光轴／景别、环境可信度、光线和画幅；
- 真人路人可以作为环境和尺度参照，但只允许出现脖子以下的躯干、手臂、手、腿、脚或无头背影；禁止可见或可辨识的真人人脸、头部、面部轮廓、眼睛、口鼻和侧脸；
- 完整、独立、可直接抽卡的首帧提示词、版本、图片地址和状态。

首帧提示词不能写“同上”、依赖上一镜、视频动作链、第二种构图、对白、口型、自动字幕或组级代指。涉及真人路人时，提示词必须明确“脖子以下／不出现真人人脸”，不能用远景、虚焦、背面或画面边缘来掩盖仍可辨识的人脸。首帧是逐镜必需产物，不是 `A-FRAME` 资产；首帧失败先修首帧，不能用视频提示词补静态身份。

### 9. 首帧验证与基于首帧的逐镜视频提示词

首帧生成／选择后，逐镜记录 `待生成 → 待选择 → 已选 → 已验证` 或 `有偏差`。只有同镜首帧已选且已验证，才写该镜视频提示词。视频提示词字段至少包括：

- `镜头编号、来源首帧修订／图片地址`；
- 视频提示词正文：从已验证首帧开始，写一个主要动作的 `起点 → 过程 → 收口`；
- `Motion Carrier`（环境、摄影机、载具、液体／粒子或角色）和摄影机运动；
- 不可改变的 Anchor、道具关系、场景拓扑、真人路人脖子以下裁切约束和负面约束；
- 建议生成时长 `4–6 秒`、预计成片裁剪区间／功能镜长、视频状态。

视频提示词只让对应首帧动起来：不得脱离首帧重新设计构图、角色、道具、摄影机，不得新增第二镜头、第二主动作、故事事实、对白、口型、自动文字或“承接上一镜最后一帧”。若首帧含真人路人，视频中只能保持脖子以下部位可见，不得让真人抬头、转脸、补出脸或生成首帧裁切范围外的头部。生成时长和成片镜长分开记录；没有结果时只能标记 `待验证／成片未验证`。

### 10. 逐镜视频生成、验收与回流

按镜头逐一生成 4–6 秒素材，检查角色身份、主动作可读性、道具关系、运动方向、入／出点、真人元素是否始终仅脖子以下可见、前后语义可接和稳定可用区间，再裁成片。结果偏差按来源回流：静态身份／构图／人脸错误回首帧；运动措辞错误新建视频提示词修订；动作因果、镜头边界或故事问题退回 Storyboard 或更早阶段。逐镜视频结果不能反写成新的角色设定。

### 11. 按视频组整理兼容生图资产

只在 Storyboard 已冻结且用户明确需要兼容 Seedance／预生成资产时整理资产。读取 `references/asset-prep-template.md`，按兼容视频组建立独立的“生图资产清单与提示词”修订；这不是 B 模式逐镜首帧产物，也不能把首帧从主链降级为可选 `A-FRAME`。

资产交付必须做到：

- 先按视频组判断图片依赖，但正式交付只列出实际需要资产提示词的组；无图片依赖的组直接省略，不建立“无需额外生图”空行；不要求每组填满所有资产类型；
- 每个列出的唯一资产只建立一个稳定 ID，写清类型、正式名称、来源参考图、适用视频组、必要时的特殊关联镜头、复用范围、输出规格、生图提示词、负面约束和状态；
- 只按需判断角色变体、场景板、关键道具、特效／材质；没有使用的类型不建立 ID、不填空行，不把多个独立资产拼成一张提示图；
- 生图提示词只描述资产的稳定外观和可复用事实，不写隐藏镜头切换、视频动作、台词、口型或未冻结的故事结果；
- 已有并通过验证的角色参考图不重复生图；需要新外观变体时才建立新的角色资产；
- 复杂场景确有首帧／尾帧需求时才建立 `A-FRAME`；在 B 模式中它仅作为兼容分支中的额外首帧／尾帧参考，不得代替每个真实镜头的 B 模式首帧提示词；
- 资产生成结果只能记录为 `待验证`、`已验证` 或 `有偏差`，不能把一张未核验图片直接当成角色连续性事实。

只有用户明确要求旧式组级 Seedance 时，才判断每组图片依赖：若必须资产尚未定义，当前轮交付“生图资产清单与提示词”并停止；若资产已定义但未验证，保持兼容 Seedance `待确认`。这条资产门不阻塞已经通过首帧验证的 B 模式逐镜视频提示词。

### 12. 转成 Seedance 直投兼容组

只在用户明确要求“一组一次提交”或已有平台约束时做生成适配。主题、大纲、角色情节和 Storyboard 必须冻结；兼容组还要声明覆盖镜头、组别映射、来源首帧／视频提示词和资产依赖。不得借“模型稳定性”把动态桥段改成静态状态帧，也不得把原本有切镜价值的整组退化成一个长镜头。兼容组不能取代 B 模式逐镜提示词。

每个 Seedance 组在净输入块之前必须声明：

```markdown
- 所属脚本：[独立脚本地址]
- 当前修订：[修订___；组号只写在产物名和文件名]
- 来源 Storyboard：[Storyboard 文件地址与修订]
- 来源首帧／视频提示词：[逐镜首帧提示词-修订___／逐镜视频提示词-修订___]
- 覆盖镜头：[镜头___—镜头___；逐项列出，不允许遗漏或重叠]
- 组别映射：[第N组；N-1=镜头___，N-2=镜头___……]
- 必保留事实：[核心触发、主要动作、即时反应、可见结果、进入下一镜的持续状态]
- 允许适配：[只列机位措辞、动作简化或生成约束中不改变画面事实的部分]
- 禁止提前／删除：[不得提前出现的结果，以及不得为稳定性删除的核心兑现]
```

来源 Storyboard、来源首帧／视频提示词、覆盖镜头或必保留事实任一缺失时，不写兼容 Seedance 净输入；若适配需要删除核心触发、结果或改变镜头覆盖，先把当前组标为 `已失效` 并退回 Storyboard 或对应逐镜产物产生新修订。

短生成组只需完成本组局部闭环，不要求在每个 8—15 秒组内同时塞入整集的三级升级、高潮余波和完整恢复。先按总秒数列出必要信息：建立、变化、结果；若所有必要动作无法各自在所属镜头内完整读出，减少次要动作或把后果移到下一组，不能让互不相关的事故并发，也不能压缩到因果倒序。

#### 生成单位与镜头单位

- **一组**是一次完整提交、一次完整生成的单位；一组可以包含多个真实切镜。
- **一个镜头**是两个剪辑切点之间的一段连续画面，只能有一个机位、一个景别和一个主要动作中心。一个连续动作可以在同一机位内完成起因、推进和结果，但不能暗藏换机位、跳时、插入特写或另一个切镜。
- 镜头标题统一写 `镜头3（2秒｜稳定35mm群像中宽景）`。只写相对整数秒，不写绝对时间码、小数秒或 `00:09—00:14`。
- 组内镜头秒数之和必须等于本组总时长。镜头数按信息和动作决定，不默认“一组一镜”，也不为快切而轮流点名角色。
- 不设通用的“8秒最多几镜”或“每镜至少几秒”。1秒可以承担一个立刻可读的动作／反应，较长镜头可以承担一个持续演进的动作；只要单镜需要用“同时／另外／镜头转到”串起互不相关的信息，就应拆镜或删除次要动作。
- 每个短镜头承担不同功能，例如建立空间、个体反应、道具阻力、POV 发现、速度比较或高潮结果；复杂群像优先用远景交代空间与结果、近景交代单个反应。

#### 可执行镜头描述

镜头正文必须是**可以直接交给视频模型执行的拍摄指令**，不能只写“某角色做了什么”的动作摘要。每个镜头按以下顺序写，缺一项就退回补充：

1. **场景与摄影机**：镜头正文第一句必须回指场景A／B／N中的一个场景模块，并同时写具体场景位置、**成片摄影机**相对主体的方位、光轴朝向、固定／手持／跟拍、焦段、景别和必须保留的空间关系。“侧面”必须说明是“相对谁的侧面”以及镜头朝向哪一侧；不能只写“侧面35mm中宽景”。镜头标题中的稳定／手持、焦段和景别必须与正文一致。例如：`场景A的游乐设施入口内侧，成片摄影机固定在Beer正前方，光轴朝向针柱墙，35mm中近景，针柱墙、Beer壳面和后方三只朋友保持在同一空间关系内。`
2. **角色与初始状态**：每个镜头中首次提及的每个可见角色都用参考图绑定的正式名称，例如 `【参考角色A：Garden】`、`【参考角色B：Beer】`，并重新写该镜头开镜时的绝对位置、朝向、身体结构、服装、持有物和正在保持的状态。不能只写“Garden已绕到另一侧”“Beer位于推出侧”“侦探蜗在边缘”；必须说明它相对哪个固定物、哪一面、距离大约多少、面对什么、画面内手持相机是否在手中。若角色持有相机，统一称为**画面内手持相机**，并明确角色看向、对准或遮挡的是它还是成片摄影机。
3. **按先后排列的动作链**：使用“先、再、随后、最后”逐项写可见动作。每个连续动作都要写出开始状态、运动过程（方向、次数、距离或力度表现）和结束后保持的状态；“连续”“用力”“轻轻”不能单独代替这些信息。一个镜头可以包含同一动作中心下的连续微动作，例如“套腕带 → 向外扯一次 → 举起画面内手持相机 → 盖住成片摄影机”，但不能把换机位、插入特写或第二个独立动作藏在“同时／随后”里。
4. **动作关系与物理因果**：写清谁接触谁、接触点在哪里、运动朝哪个方向、阻力或位移如何发生、哪个变化触发下一个角色反应。不要只写“产生反应”“自然退开”“针柱推进到安全距离”；改成“针柱前端先抵住Beer的杯形壳正面，Beer保持壳面接触不重复施压；针柱向Garden所在墙面推进，麦当劳蜗先把壳体转成侧面让出正面空间，侦探蜗随后沿墙向后退半个壳身”。
5. **角色动作的主从关系**：明确一个前景主动动作中心；其他角色只能做与该动作有直接因果的观察、避让、跟随或共同结果，并按反应先后写清谁先、谁后。若Garden拍摄、Beer操作针柱、麦当劳蜗搬道具、侦探蜗另行调查都需要独立注意力，应拆成多个镜头，不要用群像中宽景把四条动作线压在一起。
6. **镜头收口与转场**：写出动作停止后的最后一帧、所有关键角色和道具保持的状态，以及切镜方式。若用遮挡转场，必须写清遮挡物从哪一侧进入、覆盖哪个前景对象、何时完全填满全部画幅、是否保持一瞬，以及它如何直接作为下一镜切入；不能只写“做转场”“自然结束”或“切到下一镜”。

构图必须让主要动作中心、关键接触点、触发者和反应者在动作发生时可见；若装置、道具或前景角色会遮挡它们，调整成片摄影机机位或拆镜。最终交付中的每个镜头都完整展开，不使用“同上”“按同一结构”“延续前镜”等代称。

动作描述优先使用可观察的身体或道具动词：套入、扣住、扯回、举起、对准、抵住、压住、推开、转侧、退后、盖住、遮满、停住。避免用“自然、适当、轻轻互动、表现紧张、清楚可见、合理避让、随后反应”等不可检验的概括词；如确实需要力度或节奏，改写成次数、方向、距离、持续状态或接触结果。

**合格句式示例：**

> 场景A的普通现代住宅卧室门口，成片摄影机固定在门外走廊正中，光轴垂直穿过完整门框朝向卧室内，35mm正面中近景，门框和Garden上半身始终完整入画。【参考角色A：Garden】开镜时站在门框内侧约半个壳身处，身体正面朝向成片摄影机，已经背好旅行包，画面内手持相机贴近身体前侧；先把画面内手持相机的腕带套进参考图中已有的前肢，再把腕带向身体外侧扯动一次，腕带绷紧后仍套在前肢上。Garden随后举起画面内手持相机朝向自己的面部，但眼睛越过它看向门外的成片摄影机，发出一声短促的非语义招呼声，最后用同一前肢从画面下方向成片摄影机镜头中心推进并盖住它。前肢贴近成片摄影机后形成失焦深色遮挡，继续推进直到纯黑遮挡完全填满整个画幅并保持一瞬，直接硬切为下一镜。

**多人同框的合格写法：**

> 场景A的游乐设施入口内侧，成片摄影机固定在针柱装置无侧板的开放框架外，光轴垂直于针柱的水平推进方向，35mm侧面中宽景；这个机位从侧面无遮挡看见Beer近侧壳面、针柱横向位移和装置另一侧三位朋友，关键接触点与反应者不能被针柱墙遮住。【参考角色B：Beer】开镜时位于针柱装置近侧约一个壳身处，身体正面朝向针柱，没有持有其他道具；先向针柱滑行，壳面接触第一排钝头针柱后继续向前压入半个壳身，随后停止施压并保持杯形壳正面贴住针柱。【参考角色A：Garden】开镜时站在装置远侧外约两个壳身处，身体侧面朝向针柱、眼睛看向Beer，前肢持有画面内手持相机并始终对准针柱横向位移，只跟随拍摄，不操作装置。【参考角色C：麦当劳蜗】开镜时位于装置远侧的针柱推进轴线上，身体正面朝向针柱，没有持有道具；针柱前端推进到距其身体正面约一个壳身时，先把壳体向外转成侧面并保持，让出推进轴线。【参考角色D：侦探蜗牛】开镜时位于麦当劳蜗后方靠墙半个壳身处，身体朝向装置，没有持有道具；看到麦当劳蜗完成转侧后，再沿墙向后滑动半个壳身并停住。最后针柱停止推进，Beer保持壳面接触，Garden保持举起画面内手持相机拍摄，麦当劳蜗保持侧身，侦探蜗牛保持退后位置，直接硬切下一镜。

这类写法的重点不是把句子写长，而是让模型知道**场景在哪里、镜头看什么、角色从什么状态开始、动作按什么顺序发生、谁触发谁、画面在哪里结束**。

#### 每组必须自包含

视频模型看不到其他组的画面或文字。禁止用“承接上一组最后一帧”“延续上一组”“上一组浪声接入”等跨组指代替代描述。每组首帧完整重建：

- 出场角色的身份、数量、位置、队形和朝向；
- 每件关键道具由谁持有、处于何种开合／干湿／松紧／损坏状态；
- 环境、水线、天气、地面痕迹和固定地标的当前状态；
- 摄影机所在位置、光轴方向、焦段和景别。

同一组内部可以引用“匹配镜头1”等已生成上下文，但关键状态仍应在发生变化的镜头中重复。先在内部建立状态账本：`对象 → 初始状态 → 允许变化的镜头 → 变化后状态`；物件一旦掉落、打湿、打开或损坏，后续不得复原、换手或提前出现结果。

#### 场景、空间与方向

- 默认只用参考图锁角色和复杂道具；场景写成独立“场景提示词”文字模块，不把未上传的场景图当必要上下文。角色不能只写内部名字，必须写清角色字母与参考图编号的绑定关系。
- 用真实空间拓扑定义运动，例如 `海水与湿沙 → 岸上干沙 → 木质栈道入口 → 岸上高处`，不要主要依赖“画面左边／右边”。
- 明确起点、目的地、角色前方、壳后方和被远离的危险来源。头部、眼睛、触角与身体前端朝目的地；拖行物尾部和旧位置留在身后。
- POV 必须写摄影机位于哪一侧、朝哪个地标拍、谁应入画和谁不应入画。需要稳定运动方向时，明确禁止倒退、横走、跨轴和镜像翻转。
- 当笑点依赖速度差或距离变化时，用木桩、沙纹、门框、垫子旧位置等固定地标作标尺，让角色位移和环境位移在首尾匹配镜头中可直接比较。

#### 因果、群像与结果

- 事件型生成组优先完成一个局部闭环：`正常行动 → 环境施力 → 即时反应 → 可见结果`。如果笑点必须看到“被追上”“掉落”或“失败”，起因与首次结果应在同一组完成；下一组只表现已经发生的后果和新变化，不重新生成同一事件。纯建立、满足、环境或呼吸组可以只承担感官／节奏功能，不强行添加物理后果或额外反应。
- 环境前缘、角色位移和道具状态只能沿一个方向推进。上一镜已经接触，下一镜不得回到“即将接触”；未到兑现镜头的后果不得提前发生。
- 多角色可以同框，但动作必须服从同一个因果中心。不要同时安排数个互不相关的角色动作；近景完成个体反应，群像镜头只保留共同动作或共同结果。
- 每组明确“允许本组发生的变化”和“禁止提前发生的后果”。禁止项不能否定本组核心高潮；例如需要普通大岸浪时，应禁止海啸、风暴、深水、卷走和救援感，而不是禁止“大浪”。
- 角色身份、数量、壳、颜色、服装和配饰不得互换或复制。“普通朋友”只定义关系，不抹平即时反应差异，也不把差异固化为职业或长期职责。

#### 三个制作交付分层

使用 `references/templates.md` 的 Seedance 字段顺序，但以本 skill 的来源逐镜、覆盖镜头和必保留事实声明为前置契约。从标题和“总时长”到“本组禁止”是一组可直接提交给 Seedance 的完整净输入；台词分镜组别对应表和生图资产清单是独立并列产物，不附在净输入块内。

Seedance 块内不写台词表内容、角色语义对白、真人旁白、自动文字生成、中文文字渲染或口型同步要求。声音只写环境声、音乐、物理音效和非语义短促反应声。台词只进入台词分镜组别对应表，不是配音指令；其 `组别-镜头` 必须与 Seedance 覆盖镜头使用同一冻结映射。

#### 兼容 Seedance 生成结果验证与回流（不新增阶段）

兼容 Seedance 提示词通过只表示“可提交”，不表示成片已经兑现故事和角色。兼容提示词交付后把对应组的生成结果状态记为 `待验证`；只有用户提供生成结果地址／标识或可查看文件后，才在同一兼容 Seedance 组修订和 `版本记录.md` 中追加“生成结果验证”，不得新造创作阶段或产物分类。B 模式逐镜视频素材的验证按“逐镜视频生成、验收与裁剪”记录，不转成组级验证。

生成结果验证固定记录：`生成结果地址／标识、来源兼容 Seedance 修订、故事兑现、角色兑现、连续性、生成偏差、用户判断、处理决定`。若偏差只来自提示词措辞，新建该兼容 Seedance 组修订；若暴露逐镜动作、故事因果或角色情节本身有误，按失效矩阵退回最早受影响上游。没有生成结果证据时只能写“成片未验证”，不能声称动画已经有趣或角色已经兑现。

兼容分支的全片关键组通过，或 B 模式全片逐镜视频素材完成验证后，更新 `vlogs/脚本总表.md` 的“跨集机制与成片验证索引”；角色选择同时在 `vlogs/角色连续性记录.md` 区分 `剧本已冻结` 与 `成片已验证`，后续角色判断不得把未兑现的生成结果说成已验证事实。

### 13. 执行质量检查

提交前逐项通过：

- **人类测试**：换成普通朋友，这趟活动仍值得看。
- **静音测试**：不读取台词格，主要事件仍能看懂。
- **B 三曲线测试**：单日／跨日 B 模式明确时间、任务、关系三条曲线的起点、主要变化和终点；非日程或单人故事只填写适用曲线，并为不适用曲线写替代证据。
- **B 波形测试**：B 模式有基线、上升、早期小回报、主动回落、再次上升、核心记忆事件、后果／恢复和 Ending Ceremony；不把单调升级或快切当成完整故事。
- **B 三层映射测试**：核心场景—事件模块、连续故事段和真实切镜数量不混用；每个段落有完成结果或下一场触发，样本容量只是参考。
- **B 任务弧测试**：每个重要任务至少可回答目标、准备／过程、变化／Reaction、完成；任务之间有因果、时间或关系连接。
- **B 删除测试**：若段落既不改变状态、完成承诺／提出期待、推进适用曲线或替代证据，也不留下必要结果，删除、合并或重写。
- **B 主题串联测试**：短途出游／城市旅行的主题必须串起整段经历；主要任务只是其中一个核心模块，饭后或任务完成后要有后续独立活动或状态。若结构变体仍写成 `生活任务`，必须有用户明确的单项任务范围，否则退回大纲。
- **B 主题节奏测试**：分别填写主题承诺首现、主题场域建立、第一次主题兑现和核心记忆事件；主题信号通常在前 `0:00—0:15`，普通出游／日常最迟约前 `0:30—0:35` 建立场域并在前 `0:30—0:45` 给第一项主题动作／小回报，冷开场可在前 `0:00—0:06` 直接给主题。核心事件后置到 `51%—79%` 不算主题延迟。
- **B 密度与模块时长测试**：参考样本约 `15秒` 换一次核心事件、普通连续故事段约 `8.5秒`（中位数约 `6.1秒`），普通核心模块多为 `10—25秒`，重过程模块 `34—45秒`；单一任务超过 `45秒` 必须证明内部有结构性换挡，超过 `60秒` 默认退回，不得把 `70秒` 茶楼／早茶微步骤写成整集主线。
- **B 地点承载测试**：每个地点在当前连续阶段默认只承载一项任务或一次小起伏；同一物理地点可以再次出现，但必须说明任务、时段、关系或能量已切换，不能把同一任务伪装成多个地点或多个宏观模块。
- **B 能量／节奏分离测试**：故事能量和剪辑节奏分开填写；高能不必快切，高潮不必最长。
- **台词表测试**：台词分镜组别对应表中的有效节拍具有观察、反应、关系或包袱；删除这些台词会损失口吻和喜剧层，而不只是少了动作说明。
- **去标签测试**：删掉职业、名字和设定说明，行为仍自然。
- **删除测试**：删掉任一限定角色或彩蛋，故事仍完整。
- **自然时段测试**：删掉夜间限定角色后，活动是否仍有独立理由持续到夜晚；若没有，连同人为添加的夜景段一起删除。
- **闭环测试**：局部桥段快速产生结果，不等待很久才揭晓。
- **结果与状态测试**：高潮留下可读的结果或持续状态；若产生湿、乱、歪、空、破、累等物理后果，后续镜头必须保持并处理。
- **整集收束测试**：整条 VLOG 的高潮后存在处理、余波、整理、休息或继续体验；不要求每个 8—15 秒生成组都在组内完成恢复。
- **截图测试**：至少有 2—3 个无需文字也值得截取的画面。
- **原创测试**：只借用机制，没有成组照搬参考视频的场景、顺序和笑点。
- **案例独立测试**：新稿不能只是把内部已通过案例的潮水换成雨、热浪、人群或其他外力；核心事件、解决方式和高潮画面必须独立成立。
- **角色测试**：没有角色因名字、外形或职业被迫执行固定任务。
- **逐镜首帧覆盖测试**：每个 Storyboard 真实镜头恰好一条首帧提示词；空镜、Reaction、重复机位和黑场没有被删；首帧提示词独立完整，不依赖统一前缀或上一镜。
- **首帧类型测试**：每镜明确使用 `Action Start`、`Payoff State`、`Ongoing Motion State` 或 `Stable State`，并写出角色 Anchor、首帧状态、道具关系、摄影机关系和环境可信度。
- **首帧验证门测试**：首帧未达到 `已选／已验证` 时，该镜没有可提交的视频提示词；首帧错误回首帧修订，不用视频 prompt 修静态身份。
- **视频绑定测试**：每条视频提示词引用同镜首帧修订和图片地址，只描述一个主动作的起点、过程、收口；没有重新设计构图、角色、道具、摄影机或第二镜头。
- **生成长度测试**：视频 prompt 记录建议生成 4–6 秒和独立的成片裁剪区间；不把生成长度冒充成片镜长。
- **逐镜结果测试**：有视频结果时逐镜记录角色身份、主动作、道具关系、方向、入／出点、语义连续性、稳定区间、偏差和用户判断；无结果时明确标记“成片未验证”。
- **兼容生成单位测试**：只有用户明确采用旧式组级流程时，一组才是一次提交；组内真实切镜、秒数和顺序均可计算，不能把“一次生成”误写成“一镜到底”。
- **自包含测试**：B 模式每个首帧能独立还原该镜角色、道具、环境和摄影机；兼容 Seedance 组也不能依赖“上一组最后一帧”。
- **连续性测试**：固定地标、运动方向、环境前缘和道具状态在 Storyboard 与逐镜结果中单调推进，没有重置、提前结果或复原。
- **下游同源测试**：台词表、首帧表、视频 prompt 表和兼容资产／Seedance 均声明同一 Storyboard 修订；兼容组另声明组别映射；视频 prompt 不含台词表内容或整段生图提示词。
- **兼容资产覆盖测试**：只有用户要求兼容分支时才逐组判断图片依赖；只为实际需要预生成的资产建立唯一 ID、独立提示词、输出规格、来源和状态，无图片依赖的组不建立空行。
- **资产边界测试**：兼容生图提示词没有新增故事、角色职责、镜头动作或台词；兼容 Seedance 净输入只引用已冻结／已验证资产，不复制生图提示词。

若用户评价“刻意”或“没意思”，不要用更多台词、设定、反转或角色补丁修补。定位最早失败的步骤，从那里重做。

| 把“每镜一首帧／一视频 prompt”误解为一组一次生成，或把“一组一次生成”理解成一组只能有一个长镜头 | B 模式按真实切镜逐镜交付；兼容组按真实剪辑点重拆镜头，保留整组一次提交 |
| 一个镜头内写入换机位、插入特写、跳时或多个独立动作 | 拆成多个真实镜头，并重新核对总秒数 |
| 镜头正文只是“角色＋动作”的摘要，缺少场景／摄影机、初态、动作顺序、触发关系或最后帧 | 按“场景摄影机 → 角色初态 → 先再随后最后 → 接触触发 → 收口转场”重写 |
| 第一行只写“侧面／中景／近景”，没有相对谁、朝哪里和必须保留的空间关系 | 补完整机位、光轴、焦段、景别和空间锚点 |
| 角色只写内部名字或“已绕到另一侧／位于推出侧／在边缘” | 使用 `【参考角色X：正式名称】`，补相对固定物的位置、朝向、距离和持有物 |
| 用“同时”串起多条主动动作，或把拍摄者、操作者、搬运者、调查者都塞进同一群像镜头 | 保留一个主动动作中心，其余只写被触发的反应；需要独立注意力就拆镜 |
| 用“自然、合理、清楚可见、轻轻互动、随后自然退、安全距离”等评语代替动作事实 | 改成接触点、方向、次数、距离、位移和结束状态 |
| 没有写动作结束后的保持状态或只写“做转场” | 明确最后帧、遮挡物进入方向、全画幅覆盖和直接切入方式 |
| 依赖“上一组最后一帧”或其他镜头生成结果建立 B 模式首帧 | 在本镜首帧 prompt 中重写完整角色、道具、环境与摄影机状态 |
| 角色朝向只靠画面左右，或运动目标可能被生成为相反方向 | 用真实地标拓扑、身体朝向与摄影机光轴重写 |
| 环境或道具状态跨镜重置、结果提前发生或后果复原 | 建立状态账本，锁定首次变化镜头与变化后状态 |
| 为提高稳定性把动态因果改成静态停留 | 保留主要动作，减少并行动作或改用远近景分工 |
| 逐镜视频提示词混入台词表内容、语义对白、旁白、口型或自动文字 | 从视频 prompt 删除；台词只进入同源的台词表 |
| 兼容 Seedance 净输入复制整段生图／首帧／视频提示词，或在视频转换时临时发明资产 | 从净输入删除；只引用已验证资产 ID、修订、文件地址和首帧／视频来源 |
| 用户同轮要求兼容生图资产与 Seedance，而必须资产尚未定义或验证 | 按兼容制作依赖先交生图资产清单与提示词；说明图片验证后再冻结兼容 Seedance，不附带半成品净输入 |
| 用户同轮要求首帧和视频提示词，但首帧尚未生成／选择／验证 | 当前轮只交首帧提示词或首帧缺口，停止在首帧验证，不附带视频 prompt |
| 在没有生成结果及用户判断时声称动画已经有趣或角色已经兑现 | 标记“成片未验证”；等待结果后在同一组修订记录验证与回流 |

## 输出阶段

每轮原样使用 `references/production-versioning.md` 的权威产物头部，再按 `references/templates.md` 增加当前阶段、参考基线和本轮边界；不得临时拼接另一套字段。下面各节是互斥的阶段交付，不是一次输出的章节目录。

### 主题讨论／定稿

使用主题讨论或主题定稿模板，只交付工作标题、一句话生活愿望、推荐主题、2—3 个不同且可见的观看承诺、每个承诺的 `主动动作 → 环境／物体／身体变化 → 可见结果／收口`、蜗牛不可替代点、与三条最新脚本及历史机制的具体差异、核心体验、环境变化方向、边界、风险和待确认项。不同地点或不同对象不算不同机制。缺少任一硬证据时主题保持 `讨论中`，不得冻结。此阶段不列最少角色、不写完整因果链、逐段大纲、分镜、台词表或 Seedance。用户确认后把当前主题修订标为已冻结并停止；下一轮才开始故事大纲。

### 故事大纲

主题已冻结后，读取 `reference-mechanics.md`、`ganamao-six-script-deconstruction.md`、`b-vlog-scene-architecture.md` 和 `b-vlog-story-arc-framework.md`（B 模式），使用故事大纲模板交付从开场到结尾的完整故事、主要可视桥段、活动真正好看的部分、局部笑点、升级、核心记忆事件、可见结果、后果／恢复、`Ending Ceremony` 和结尾余味。B 模式先以原始样本完成校准：明确结构变体、新鲜感发动机、体验主线／活动链、核心模块链、每模块时长预算和模块间触发；再交付并核对适用的时间／任务／关系曲线、波形和核心场景—事件矩阵，最后写故事段落；通用模式按活动需要组织。只使用故事语言，不写机位、焦段、正式逐镜编号、Seedance 指令或正式台词。故事迁移的是三条最新脚本的行程骨架与局部闭环机制，但必须更换活动、因果、道具和高潮；事件型桥段写清动作、变化、反应和结果，纯准备、满足或景色段允许由动作状态和情绪停顿成立；若高潮留下持续后果就写出处理／恢复，否则安排关系反应、继续体验、情绪降速或安静余波。角色只写故事确实需要的同行规模和互动关系假设，不在此阶段点名或完成逐角色任务分配。大纲冻结后，把活动、环境发动机、核心因果、高潮机制、可见结果和关系变化写入 `vlogs/脚本总表.md` 的跨集索引；这只是共享证据更新，不新增阶段。完成后等待用户确认大纲。

### 角色情节设计

主题和大纲确认后，使用 `references/reference-mechanics.md` 的角色呈现原则和 `references/templates.md` 的角色情节设计模板，并读取可核实的跨集行为依据。逐桥段写角色在场理由、当下目标、选择、动作、反应、与朋友的关系变化和可见笑点；逐角色另列过去冻结行为的地址／修订、本集延续倾向、本集变化或反例、最近避免重复的动作和关系动作。角色差异必须像三条最新脚本一样从同一事件下的判断、抢先、犹豫、逞强、跟随、自保、补救或纠偏中泄露，不把参考样本中的角色职能原样搬来。先审查角色是否真的需要，再分配情节；不得为了让每个角色露脸而补职责，也不得在没有跨集证据时发明永久性格。完成后等待用户确认角色情节，再进入逐镜脚本。

### Storyboard（逐镜视觉）

使用 `references/reference-mechanics.md`、`references/ganamao-six-script-deconstruction.md` 和 `references/templates.md` 的逐镜视觉字段，写明时间、场景位置、摄影机方位／焦段／景别、参考角色正式名称、开镜位置与朝向、持有物和身体状态、按先后排列的动作链、接触与触发关系、环境变化、反应、持续状态、声音及镜头收口／转场。B 模式每行额外回指已冻结的核心模块、连续故事段和故事功能，写清进入／退出状态与下一场触发；故事功能使用 `Entry / Threshold / Task / Payoff / Recovery / Ending Ceremony` 六类规范标签，可在标签后加“小回报／核心记忆”等子类型；不能在 Storyboard 里重新选择核心记忆事件或补出上游没有的波形。镜头应按当前故事需要取用三条脚本中出现的功能：生活／POV进入、移动集合、活动对象、个体反应、群像结果、高潮结果、后果处理／继续体验／安静余波和收束；这不是固定镜头清单或固定顺序。视觉稿不填写正式台词。不得在逐镜阶段擅自新增主线、角色任务或世界观，也不能用“自然互动”“随后反应”“合理避让”“清楚可见”等抽象摘要替代可观察的方向、距离、次数、接触点和结果。

Storyboard 稿完成后同时冻结视觉事件、全片连续镜头号、每个桥段的兑现镜头、每镜的时间／章节、动作收口和状态账本。只有用户明确采用兼容 Seedance 组级一次提交时，才额外冻结组别边界、组内顺序和 `组别-镜头` 映射；它不是 B 模式首帧的前置条件。任一视觉事实或镜头边界未确认时，不进入任何逐镜首帧提示词。用户确认 Storyboard 修订后，才把其中可见的角色选择和关系动作以 `剧本已冻结` 回写到 `vlogs/角色连续性记录.md`，并记录脚本地址、来源角色情节、来源 Storyboard 和兑现镜头；成片核对后再改为 `成片已验证` 或记录偏差。相关来源失效时同步把这些证据标记 `已失效`。

### 逐镜首帧提示词与首帧验证

只在 Storyboard 已冻结后，使用 `references/templates.md` 的逐镜首帧模板。每个真实切镜恰好一条独立首帧提示词，逐行记录首帧类型、角色 Anchor、静态状态、道具关系、摄影机关系、环境可信度、真人路人脖子以下裁切约束、版本、图片地址和状态。首帧提示词完成后先请求用户确认或执行首帧生成／选择；未达到 `已验证` 的镜头只保留首帧缺口，不写视频提示词。

### 基于首帧的逐镜视频提示词

只在对应镜头首帧已选且已验证后，使用 `references/templates.md` 的视频提示词模板。每镜视频 prompt 只写一个主动作的起点、过程和收口，并绑定同镜首帧修订／图片地址；明确 Motion Carrier、摄影机运动、不可改变 Anchor、真人路人脖子以下裁切约束、4–6 秒生成建议和成片裁剪区间。视频 prompt 不重新设计静态构图，不写上一镜／下一镜依赖、第二镜头、对白、口型或自动字幕；不得让首帧中的真人路人露出或生成真人人脸。附件样例没有视频 prompt，新增格式是本项目生产契约，不应声称来自参考样本。

### 逐镜视频生成、验收与裁剪

有视频结果时逐镜记录生成文件、稳定可用区间、角色身份、主动作、道具关系、运动方向、入／出点、真人人脸违规、语义连续性、偏差、用户判断和处理决定；没有结果时标记 `成片未验证`。4–6 秒是素材生成建议，最终成片镜长另列；首帧静态人脸错误回首帧，视频中补脸或露脸错误改视频 prompt，Storyboard 因果错误退回 Storyboard。

### 台词分镜组别对应表交接（独立分支）

只在 Storyboard、全片镜头号、时间戳、画面／动作／声音事实和角色情节均已冻结后交接。若用户采用兼容 Seedance，再核对组别映射；B 模式首帧／视频状态不是台词表的替代输入。核对完整后调用 `writing-snail-vlog-subtitles`；本 skill 不编写台词格、不生成候选表，也不直接创建台词表修订。输入缺失时只列最早缺口；输入完整时由唯一写入者按其模板输出五列表。

### 生图资产清单与提示词（兼容分支）

只在用户明确需要兼容 Seedance 或复用图像资产时，使用 `references/asset-prep-template.md` 输出一份稀疏的按组资产提示词清单。只列出确实需要提前生图或固定图片锚点的组；没有图片依赖的组省略，不建立空行。每个列出的资产按需写正式名称、类型、来源参考图、适用视频组、必要时的特殊关联镜头、复用范围、生图提示词、负面约束、输出规格、状态和修订。没有使用的 `A-CHAR`、`A-SCENE`、`A-PROP`、`A-FX` 或 `A-FRAME` 不建立 ID。`A-FRAME` 不能代替 B 模式首帧。资产提示词不得承载视频动作、切镜或台词。已有生成文件可查看后，在同一资产修订中记录验证；改变资产提示词才新建资产修订。

### Seedance 直投提示词（兼容分支）

使用 `references/ganamao-six-script-deconstruction.md` 的 Seedance 转换规则和 `references/templates.md` 的 Seedance 字段顺序。每组独立交付来源声明和一个完整净输入块，明确所属脚本、组修订、来源 Storyboard、来源首帧／视频提示词、覆盖镜头、组别映射、必保留事实、允许适配和禁止提前／删除；本组有预生成资产时还要声明来源资产修订、组别-资产映射、资产文件地址和验证状态，只有单镜资产才追加镜头-资产映射。净输入再写整数总时长、镜头数和“一次生成”。镜头按冻结的真实切点和组内顺序编号，使用相对整数秒。**兼容组中的真人路人也只能出现脖子以下部位，不得出现真人人脸、头部或面部轮廓；这条约束写入每组的场景／镜头正文和本组禁止。**最终稿不得残留占位符、备选写法、跨组指代或绝对时间码，也不得附带或改写台词表或复制首帧／生图提示词。必须资产未验证时基础状态保持 `待确认`，专属字段写 `资产依赖状态：待资产验证`，不能冻结最终净输入。完成后逐项执行 `references/seedance-validation-checklist.md` 的兼容分支清单。兼容提示词完成时生成结果状态只能是 `待验证`；实际结果可查看后再追加生成结果验证并按偏差来源决定新建兼容组修订或退回上游。
