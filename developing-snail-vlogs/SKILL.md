# 蜗牛拟人 VLOG 内容开发

## 1. 执行原则

把本 Skill 当成一套**分阶段内容生产协议**，不是一次性脚本生成器。

始终执行以下规则：

1. 先选择观众愿意亲自经历的真实活动，再让蜗牛进入活动。
2. 先设计完整经历和任务接力，再为每段分配地点；不得从一个地点反推整集起承转合。
3. 让角色像固定朋友一起生活；用选择、反应和关系动作泄露性格，不做轮流展示。
4. 用画面交代动作、因果、结果和持续状态；台词只补观察视角与关系笑点。
5. 区分故事能量与剪辑速度；高潮可以很短，过程必须足够具体。
6. 每轮只处理最早一个尚未冻结的必需产物；用户确认后才进入下一阶段。
7. 始终以用户当前明确决定覆盖旧稿、样本和参考文件。

事件型桥段优先使用：

> 现实动作 → 环境／物体／身体变化 → 即时反应 → 可见结果或持续状态 → 处理／恢复／关系余波 → 继续

纯准备、满足、观察或环境呼吸段不强行制造事故，但必须提供感官价值、状态变化或结构作用。

## 3. B／干嘛猫风格工作定义

把 B 定义为：

> **任务／过程驱动的拟人生活 Vlog：用固定主 Vlogger 与朋友团完成一件真实生活活动，把完整过程、微小变化、朋友 Reaction 和时间流逝拍成生活纪录。**

不要把它误写成：

- 单地点短剧；
- 连续事故合集；
- 每镜都卖萌或抖包袱；
- 只展示结果的 AI 奇观；
- 旅行地点清单；
- 平均分戏的角色宣传片。

稳定氛围是：真实公共空间和生活质感、轻松但不空洞、荒诞拟人却认真做事、朋友相处自然、高潮后仍保留恢复与余波。

## 4. 选题模型

### 4.1 五类稳定选题

优先从以下结构变体选题，再决定地点：

| 类型 | 新鲜感发动机 | 主要风险 |
|---|---|---|
| 发现驱动 | 持续更换对象、展区或观察角度 | 写成导览清单 |
| 悬念兑现 | 风险／困难逐步积累并兑现 | 只剩事故，缺少生活过程 |
| 朋友团综 | 活动接力与不同 Reaction | 平均分戏、职责标签化 |
| 生活任务 | 把一件小事的过程拍完整 | 同一动作重复过久 |
| 完整一日／户外任务链 | 同一空间连续完成不同任务并经历时段变化 | 把“没换地点”误当成“没换事件” |

### 4.2 九问筛选

在冻结主题前依次回答：

1. 观众是否愿意亲自经历这件事？
2. 是否存在明确生活目的，而不只是一个静态概念？
3. 能否拆出一串可见任务，而不是靠台词解释？
4. 至少会发生两次对象、身体、环境、关系或时间状态变化吗？
5. 活动过程本身是否好看、好吃、好笑、治愈或刺激？
6. 蜗牛身体、速度、壳或环境关系是否让题材不可替代？
7. 朋友之间能否出现判断差异和共同结果？
8. 是否能形成一个核心记忆事件？
9. 是否有自然结束信号，而不是突然停片？

选题公式：

> 明确生活目的 + 可见任务链 + 至少两次状态变化 + 一次朋友关系兑现 + 一个核心记忆事件 + 一个自然结束信号

短途题材要用更大的 umbrella 主题覆盖整段经历。例如“坐火车去邻城吃早茶”的完整选题是“一次为了吃早茶而完成的短途城市旅行”；早茶只是一个核心事件模块，不能承包整条视频。

## 5. 四层叙事架构

在逐镜前严格区分四层：

> **宏观环境块 → 核心事件章节 → 连续故事段 → 实际切镜**

| 层级 | 回答的问题 | 约 2:15—2:35 样本容量 | 使用阶段 |
|---|---|---:|---|
| 宏观环境块 | 角色先后进入哪些大的生活场域／时段？ | 5—8 个 | 主题路线与大纲 |
| 核心事件章节 | 在每个环境中完成哪些独立任务／经历？ | 8—11 个 | 故事大纲 |
| 连续故事段 | 任务、对象、关系、时段或能量何时换挡？ | 11—25 段 | 场景编排 |
| 实际切镜 | 每个可见动作、Reaction、结果和呼吸如何剪开？ | 46—67 镜 | Storyboard |

五条样本的大环境转场约 `4—7` 次，平均约 `5.6` 次；宏观环境块平均约 `6.6` 个。把这些数字当作**诊断基准**，不得当作机械配额。

“宏观环境”是创作归并，不等于房间名称：同一物理地点发生明确时段、活动家族或能量变化，可以形成新的宏观块；跨越多个路点的出发蒙太奇也可能只属于一个移动块。

“核心事件章节”必须有统一目标和完成状态。点餐、等待、揭盖、处理菜品、吃饭、结账通常只是餐食章节内部步骤，不得靠改标签伪装成六个大事件。

## 6. 主题时机、双时钟与时长

### 6.1 主题与高潮分开记录

同时保留“样本观察范围”和“推荐创作目标”：

| 节点 | 样本观察 | 推荐目标 | 作用 |
|---|---:|---:|---|
| 主题承诺首现／Hook | 0—15s | 0—10s | 看见对象、关系、目标或问题 |
| 主题场域建立 | 15—35s | 10—30s | 明确今天实际要做什么 |
| 第一次主题兑现 | 30—45s | 20—35s | 第一项真实动作或小回报发生 |
| 核心记忆事件 | 成片 51%—79% | 依故事安排 | 最值得记住的动作、喜剧、完成、关系或情绪时刻 |

核心事件可以后置，主题本身不能后置。前一分钟只有泛化起床、交通和准备，直到 `1:00` 才开始标题承诺，默认退回大纲。

### 6.2 同时运行两只时钟

| 时钟 | 参考范围 | 到点必须发生什么 |
|---|---:|---|
| 事件更新时钟 | 通常 8—20s | 任务、对象、信息、关系、身体或结果至少一项更新 |
| 宏观环境时钟 | 通常 15—30s；主场地可更长 | 换场域／时段，或证明当前场地仍有新任务支撑 |

执行以下诊断：

- 同一宏观环境累计超过约 `30s`：至少列出 2 个有效事件章节。
- 同一宏观环境累计超过约 `60s`：通常列出 3—5 个事件章节，或发生清楚的时段／能量转向。
- 同一任务连续超过 `45s`：标注内部动作、对象、关系、身体或能量换挡；写不出则压缩。
- 同一任务连续超过 `60s`：默认重做体验主线，除非整集明确就是该任务且内部状态链足够独立。
- 连续故事段超过 `15—20s`：写明持续观看价值和内部状态变化；否则拆分、压缩或换任务。

注意：“同一环境过长”与“同一任务过长”是两种不同问题。同一溪边可以用搭营、餐食、抓鱼、玩水和夜间活动成立；同一茶桌重复吃喝不能因为镜头多就成立。

### 6.3 镜头节奏

样本实际切镜均值约 `2.64s`、中位数约 `2.17s`，约 90% 不超过 `5s`。按镜头功能调整，不按平均值机械切：

- 操作 Detail／Insert：约 0.8—2.5s；
- 普通行动／Reaction：约 1.5—3.5s；
- Selfie／Group：约 2—4s；
- 环境／呼吸：约 2.5—5s；
- 强状态／情绪：约 3—6s。

使用“快过程＋慢状态”：把操作过程拆快，把完成结果、关系反应、环境变化和余波留住。

## 7. 故事弧与转场

同时规划三条曲线：

| 曲线 | 典型走向 | 可见证据 |
|---|---|---|
| 时间 | 早晨→白天→午后→黄昏→夜晚 | 光线、装备、环境、活动时段或跨日重置 |
| 任务 | 目标→准备→执行→变化／Reaction→完成→休息／转场 | 每个任务如何开始、完成并留下状态 |
| 关系 | 独处／分散→会合→共同经历→集体记忆→告别 | 成员进入、相互影响、共同结果和关系停点 |

非日程故事不强行补早晚；单人故事可把关系曲线替换为身体／自我状态曲线，并写明替代证据。

使用波浪推进而不是直线上升：

> 生活基线 → 第一次上升 → 早期小回报 → 呼吸／回落 → 第二次任务波 → 中段笑点 → 再回落 → 核心记忆事件 → 后果／恢复 → Ending Ceremony

允许合并或省略功能，但要说明替代证据。六类标准功能标签为：`Entry`、`Threshold`、`Task`、`Payoff`、`Recovery`、`Ending Ceremony`。

每个重要任务至少写出：

> 目标 → 准备／过程 → 变化或 Reaction → 完成结果／持续状态

只在以下动因成立时切到下一事件或环境：任务完成、结果产生因果后续、身体／生活需要改变、时间门槛、关系状态改变、当前对象新鲜度耗尽、需要改变能量方向。

每次切场回答两句：

1. 上一场完成了什么或留下了什么状态？
2. 为什么下一场现在必须发生？

## 8. 分阶段工作流

### 8.1 入口判定

用户提供旧稿或指定版本时，先判断它实际包含哪些产物、哪些经过明确确认、哪些上游仍有效。文件名和“按这版”不能自动冻结不存在的层级。

当前阶段始终取**最早一个尚未冻结或已经失效的必需产物**。

### 8.2 主流程

1. 主题讨论与冻结。
2. 故事大纲与冻结。
3. 角色情节设计与冻结。
4. Storyboard／逐切镜视觉脚本与冻结。
5. 每镜独立首帧提示词。
6. 首帧生成／选择／验证。
7. 基于同镜首帧的逐镜视频提示词。
8. 生成 4—6s 素材、验收稳定区间并裁剪成片。

台词表、复用生图资产和旧式组级 Seedance 是显式兼容分支，不得替代主流程。

### 8.3 阶段门槛

- 每轮只交付当前一个正式产物；可以说明下一步，但不预写下一阶段成品。
- 用户明确说“按这版继续／定稿／进入下一步”才冻结当前产物。
- 主题确认不等于大纲确认；大纲确认不等于角色或 Storyboard 确认。
- 上游事实变化时，按 `references/production-versioning.md` 标记下游失效，再回到最早受影响阶段。
- Storyboard 未冻结时，不生成首帧；同镜首帧未验证时，不写视频提示词。
- 审核整套既有产物时可以跨层列缺口，但从最早缺口开始修改。

## 9. 各阶段交付合同

### 9.1 主题

只交付：一句话生活愿望、推荐主题、2—3 个彼此不同且能在画面中兑现的观看承诺、蜗牛不可替代点、结构变体、故事范围、排除方向、与历史机制的具体差异。

不要写完整因果、角色任务、逐镜或提示词。

### 9.2 故事大纲

先完成以下结构表，再写故事正文：

1. 主题节奏表：Hook、场域建立、首次兑现、核心记忆事件。
2. 体验主线／活动链：先不写地点。
3. 宏观环境链：5—8 个作为样本参照，并标出环境转场。
4. 场景—事件矩阵。
5. 时间／任务／关系曲线与能量波形。

场景—事件矩阵至少包含：

| 宏观环境块 | 核心事件章节 | 连续故事段 | 地点语义／时段 | 进入状态 | 当前任务 | 完成结果 | 预计时长／镜头 | 下一场触发 | 故事功能／能量 |
|---|---|---|---|---|---|---|---|---|---|

大纲使用故事语言，不写焦段、正式镜号、模型指令或正式台词。主要任务完成后安排后续独立活动、恢复或结束；不得让一个消费地点承包整条旅行题材。

### 9.3 角色情节

逐桥段填写：在场理由、当下目标、主动选择、触发、动作、即时反应、朋友关系动作、持续后果。删除角色后无影响时，降为背景或移除。

没有跨集证据时，只写本集选择，不把一次行为升级成永久性格。

### 9.4 Storyboard

严格执行“原片每次真实切镜＝一行”：

- 空镜、Reaction、重复机位、贴脸、第二次同类动作和黑场，只要真实切镜就保留。
- 同一连续镜头内部的遮挡、快速运动和检测误判不另算镜头。
- 章节标签不得反向决定镜头数。

每行写明：时间、宏观环境块、核心事件章节、连续故事段、镜号、故事功能、场景与摄影机、开镜状态、一个主动作、触发与反应、最后状态、声音、收口／转场、下一场触发。

冻结全片连续镜号和状态账本。不得用“自然互动、随后反应、合理避让、清楚可见”等抽象评价代替方向、距离、接触点、次数和结果。

### 9.5 逐镜首帧

每个真实切镜生成一条完整、独立、可直接抽卡的提示词，不依赖统一前缀或上一镜。

按镜头需要选择：`Action Start`、`Payoff State`、`Ongoing Motion State`、`Stable State`。首帧不统一限定在动作 0—20%；笑点已经成立、动作正在进行或需要稳定状态时，选择相应类型。

每条包含：角色 Anchor、首帧状态、道具关系、摄影机关系、环境可信度、版本、图片地址和验证状态。

### 9.6 基于首帧的视频提示词

只描述同镜首帧之后的一个主要动作：`起点 → 过程 → 收口`。注明 Motion Carrier、必要摄影机运动、不可改变 Anchor、建议生成时长和预计成片区间。

不得重新设计构图、角色、道具或摄影机；不得加入第二镜头、第二主动作、对白、口型、旁白或自动字幕。首帧静态事实错误时回退首帧，不用视频提示词修图。

把模型输出视为“素材”而非成片镜头：生成 4—6s 后选择稳定可用区间，再按 Storyboard 镜长裁剪。

## 10. 视觉与生成硬规则

- 使用真实生活空间、公共环境尺度、普通 Vlog／运动相机语言和适度超广角；避免商业广告、电影海报和过度干净的 AI 场景。
- 用环境、动作和关系制造氛围，不依赖平面特效和解释性文字。
- 保持角色连续、任务连续、关键道具连续、场景语义连续、时间／装备连续；不要求每次严格展示完整走位。
- 使用 Motion Carrier 承担可生成运动，例如水流、车窗、烟雾、布料、道具、遮挡物或明确主动作。
- 用可控的随手拍、遮挡、运动模糊和轻微畸变做 Error Camouflage，但不得借此隐藏角色身份、动作因果或关键结果。
- 多角色镜头只保留一个主动动作中心，其余角色执行被触发的反应；需要独立注意力时拆镜。
- 真人路人只允许脖子以下部位，不出现真人人脸、头部或面部轮廓；首帧和视频结果都检查。
- 画面事实不能依赖台词补全。正式台词表交给 `writing-snail-vlog-subtitles` 唯一写入。

## 11. 硬性退回条件

遇到以下任一情况，停止下游生产并回到对应阶段：

| 问题 | 退回处理 |
|---|---|
| 主题没有可见任务、变化、关系兑现或结束信号 | 回到主题筛选 |
| 前 15s 无主题信号，前 35s 未建立主题，前 45s 无首次兑现 | 回到大纲，前置承诺与第一动作 |
| 只有地点／日程，没有四层架构和三条曲线 | 补宏观环境链、场景—事件矩阵和曲线 |
| 同一宏观环境超过 30／60s，却没有 2／3—5 个有效事件章节或时段换挡 | 重组该环境内部任务或切到后续活动 |
| 同一任务超过 45／60s，只靠微步骤填充 | 压缩或重做体验主线 |
| 切场没有完成结果或下一场触发 | 合并或重写转场 |
| 高潮后立即结束 | 补结果、恢复、继续体验或安静余波 |
| 缺少 Ending Ceremony | 补明确结束信号和关系／自我停点 |
| 角色稿未冻结便分镜 | 回到角色情节 |
| Storyboard 未冻结便生成首帧 | 回到 Storyboard |
| 首帧未验证便写视频提示词 | 停在首帧验证 |
| 视频 prompt 改写静态构图或包含第二镜头 | 回到首帧或 Storyboard |
| 一轮同时交付主题、大纲、角色、分镜和提示词 | 只保留最早未冻结产物 |
| 把样本数量当成硬配额 | 恢复内容驱动并说明偏离理由 |

## 12. 版本、状态与输出

所有正式产物绑定同一脚本地址，并使用 `references/production-versioning.md` 的权威产物头。不要覆盖已冻结稿；新建修订并记录来源、状态、用户确认和失效依据。

每轮开头写：当前脚本、当前阶段、上游冻结状态、当前修订、已读取参考、本轮边界。每轮末尾只请求当前产物的确认，并说明确认后解锁的下一阶段。

审稿或改写时，先指出最早失效的层级和证据，再修改结构；不要只润色一个结构错误的方案。

更新本 Skill 自身时，运行 `python3 scripts/validate_skill.py` 和 Skill Creator 的 `quick_validate.py`；两项都通过后再提交。
