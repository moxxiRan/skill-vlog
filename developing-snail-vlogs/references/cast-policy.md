## 1. 使用原则

### 真实世界优先

基本吸引力来自：

> 真实的人类生活场景 + 像人一样生活的拟人蜗牛

选择能直接代入的出游、聚餐、通勤、购物、下雨、做饭、海边等生活经验。不要因为已有桌宠素材，把内容锁进只有蜗牛存在的原创世界。

蜗牛的统一尺寸、人与蜗牛的关系和社会身份尚未正式确定。脚本不要擅自扩建宏大世界观或解释型 lore。

### 故事先于角色展示

角色是一起生活的朋友，不是功能卡。除 Garden 外，任何角色都不是每集必到。不要平均分配桥段，不要为阵容完整另造任务。

### 一集只使用合适的人

先确定真实活动，再选择角色。角色越多，越需要回答“为什么必须在这一集出现”。没有自然答案时，删角色，不编任务。

提示里出现“可用、备选、希望尽量露脸”只表示角色池，不等于本集必须全部出现。只有用户明确使用“必须、全部、每只都要出现”等硬性表达时，才把全员在场当约束。

## 2. 当前确认阵容

| 角色 | 当前定位 | 固定出场 | 使用要求 |
|---|---|---:|---|
| Garden／花园蜗牛 | VLOG 主角、体验锚点、主要观察或掌镜视角 | 是 | 带观众进入一天，不必制造事件、解决问题或总结主题 |
| Beer／啤酒蜗牛 | 可反复出现的普通朋友 | 否 | 可参与任何生活活动，不固定成只会喝酒或负责组局的人 |
| 麦当劳蜗（工作名） | 可反复出现的普通朋友 | 否 | 不固定承担送餐、分食物、偷吃或找餐厅等职责 |
| 侦探蜗牛 | 可反复出现的普通朋友 | 否 | 帽子、放大镜是视觉标识，不代表每次都必须查案或推理 |
| 宝箱吸血鬼蜗牛 | 夜间限定特殊角色 | 否 | 只在故事自然进入夜晚时考虑；有夜景也不强制出现 |
| Golden／金蜗牛 | 背景彩蛋 | 否 | 与 Garden 视觉接近，不推动剧情、不被台词格或镜头点名 |

## 3. 角色边界

### 3.1 Garden

可以：

- 用起床、出门、集合建立当天目标；
- 拍摄朋友和环境；
- 与大家一起遭遇活动中的意外；
- 在结尾记录合影、景色或收镜头动作。

不必：

- 主持整场活动；
- 逐个介绍朋友；
- 解决所有问题；
- 解释角色关系；
- 用旁白总结友情或人生道理。

### 3.2 Beer、麦当劳蜗与侦探蜗

进入故事时，首先都是 Garden 的朋友。外形提供识别，不自动生成剧情职责。

- 侦探蜗可以因离漂走的杯子最近而顺手捡回，但不要把故事改成“杯子失踪案”。
- 麦当劳蜗可以和大家一起吃饭，但不是默认食物管理员。
- Beer 可以参加海边、逛街、运动、做饭等任何活动，不必出现酒。

一次性的自然反应不能自动升级成永久人设。只有经过多集自然重复且团队确认，才沉淀为稳定性格。

角色情节阶段读取 `character-continuity.md` 和项目中的 `vlogs/角色连续性记录.md`（若存在）。只引用已冻结稿中的行为证据，并写清本集延续、变化／反例、近期重复风险和关系动作。没有历史证据时写“本集表现”，不能发明永久性格；同一角色连续重复“同一刺激＋同一反应＋同一笑点”时，除非结果发生变化且明确作为回调，否则重写选择。

### 3.3 宝箱吸血鬼蜗牛

用户所指角色准确对应当前 Demo 的 `vampsurvivor`，旧版还存在 `vampire2` 工作映射；普通 `vampire` 是另一只角色。正式制作仍应由资产负责人确认版本。

“夜间限定”不表示：

- 每到晚上必须出现；
- 负责夜间服务或失物保管；
- 已拥有确定的超自然能力；
- 必须神秘登场；
- 故事需要吸血鬼世界观。

若白天故事已经完整，不要为了它把时间拖到晚上。

不要通过把生活愿望改写为“待到天黑”、增加无必要的夜景尾声或延长当天行程，伪造所谓“自然出现”。先写出没有宝箱吸血鬼蜗时的自然结束时间；若活动本身不会持续到夜晚，本集不使用它。

### 3.4 Golden

允许：远景一闪而过、藏在背景合影或相似构图中、供观众自行发现。

不允许：固定压轴、台词提醒、承担因果、解释与 Garden 的关系，或临时设定为升级形态、富豪版本、奖励角色。

## 4. 非每集强制政策

禁止：

- 每集依次展示所有已确认角色；
- 给每只蜗牛平均分配台词和时长；
- 白天强塞宝箱吸血鬼蜗牛；
- 结尾固定塞入 Golden；
- 让侦探蜗每集发现“小案件”；
- 让麦当劳蜗每集负责食物笑点；
- 让 Beer 每集负责喝酒或带动气氛。

角色缺席不是设定错误。一集只用 Garden 加一至三位朋友完全成立。

## 5. 候选池与排除项

### 5.1 尚未确认进入固定阵容的较低来源风险候选

以下角色仅是后续选角候选，不是每集可直接调用的正式阵容：

- Glazegazer
- Makimuncher
- Dessert
- Dragon
- Soccer
- Tennis
- Rugby
- Ninja
- Zombie／Zom2

Poop 的来源风险较低，但品牌调性与商务适配较弱，不建议作为长期核心。

### 5.2 公共原型或文化联想较强

Vampire、Santa、Samurai／Shogun、French、Wukong、Detective／Slug Holmes 等可从公共原型重新创作，但需要避免刻板印象、专属口吻与过度接近特定作品的造型。

侦探蜗已被用户纳入可用阵容，但仍不要把“Slug Holmes”当作对外最终名称或默认福尔摩斯式性格。

### 5.3 明确禁用：萝卜蜗

用户已明确指出萝卜蜗捏他国内博主的猫。取得权利确认或完成足以摆脱原型识别的重新设计前，不得用于正式视频、彩蛋、背景路人或候选方案；改名不能解决来源问题。

### 5.4 默认不进入原创 IP 核心

库存中明显依赖名人、品牌、影视、游戏或网络形象的角色，不得因文件存在就视为可发行，包括但不限于：

- 名人或公众人物映射：Trump、Elon、Einstein、Jordan、Ali／Boxer、Elvis、PewDiePie、达芬奇、苏格拉底、特蕾莎等；
- 品牌映射：Starbeans、McD／McDonalds、Kingburger、Mycrosoft、Claude、Giggle 等；
- 作品或游戏映射：Bumblebee、Tetra、Wizard、Pirate、Vampire Survivors、Gibbrycastle、TLOU、Train to Busan、TopSnail、Shield of Legend、Snilbo Baggins、PogChamp、Top Gun、Super Bowl 等。

麦当劳蜗与宝箱吸血鬼蜗因用户已确认创意方向，保留为“可开发但必须改造／复核”的例外，不代表当前造型和名称已经清权。

## 6. 素材与版本事实

### 6.1 来源范围

用户已明确：选角不局限于最新 Demo，旧版存在的蜗牛也可进入创意候选。旧素材可候选，不等于已满足当前工程格式、清晰度、动画兼容、造型一致或发行授权要求。

### 6.2 当前资产定位

当前 Demo 的基础路径：

`E:/SteamLibrary/steamapps/common/Thirsty Snail Demo/resources/assets/snails/`

可核对到：

- `garden/v1`
- `beer/v1`
- `detective/v1`
- `golden_shell/v1`
- `mcd/v1`
- `mcdonalds/v1`
- `vampsurvivor/v1`

旧版基础路径：

`I:/snail/resources/app/assets/snails/`

其中还存在 `vampire2` 和多套历史版本。目录名只是内部定位，不等于最终公开角色名。

尚待确认：

- 麦当劳蜗采用 `mcd` 还是 `mcdonalds`；
- 宝箱吸血鬼蜗牛采用哪一版为正式资产；
- Garden 的正式视频标准造型；
- 中文名、英文名与内部 ID 的统一映射。

交付美术时，使用缩略图或明确资产路径，不只写容易混淆的工作名。

### 6.3 技术审计备注

当前 Demo `resources/assets/snails` 审计到 61 个角色目录、62 套变体、730 个 `.png` 扩展名文件，`resources` 内没有 MP4、WebM 或 MOV。抽样显示部分 `.png` 实际编码为带 Alpha 的 WebP 精灵表，尺寸并不完全一致；导入剪辑软件前应重新核对并按需转码。

旧版 `I:/snail` 存在部分历史绿幕 MP4。该差异只影响制作准备，不影响创意选角。

## 7. 动作量后置原则

用户已明确：选择角色和构思故事时，不考虑现成动作数量。

强制顺序：

1. 确定真实活动和有趣的环境变化；
2. 选择最自然进入这段生活的角色；
3. 通过静音测试；
4. 大纲通过后盘点已有动作；
5. 对缺失动作补画、重做、生成或调整镜头执行。

禁止：

> 某角色动作多 → 强行让它出演 → 根据动作库存拼故事

允许改变机位、道具运动、角色遮挡或剪辑方式，但不能把“蜗牛认真逃跑却跑不过潮水”之类的核心机制替换成一行台词。

## 8. IP 与合规风险

### 麦当劳蜗

`mcd`、`mcdonalds` 命名及可能的红黄餐饮包装具有品牌联想。对外发布前确认名称、帽子、包装、配色、图形及标题文字是否需要原创化。复核前只使用内部工作名。

### 宝箱吸血鬼蜗牛

`vampsurvivor`、宝箱、吸血鬼组合及醒目标记可能联想到特定游戏。若作为长期 IP 使用，至少重新审视公开名称、宝箱轮廓、纹样、十字装饰、色彩与“幸存到天亮／loot／奖励”等话术。仅改名不足以自动消除来源识别。

### Beer

涉及真实饮酒、醉酒或酒类品牌时，按平台、受众年龄和商业合作要求复核。不要因外形默认把它写成酗酒、失控或鼓励饮酒。

统一原则：

> 素材存在 ≠ 权利已清理；内部可运行 ≠ 对外可发行。

## 9. 尚未确定事项

不得由编剧自行写成事实：

- Beer、麦当劳蜗、侦探蜗的正式性格标签；
- 角色之间的亲属、同事、恋爱等固定关系；
- 宝箱吸血鬼蜗的能力、来历与居住地点；
- Golden 与 Garden 的关系；
- 蜗牛在现实世界中的统一尺寸；
- 人类是否能看见或理解蜗牛；
- 所有角色的性别、年龄、职业和固定口头禅；
- 对外正式名称；
- 所有素材的完整授权状态。

- [ ] “可用／备选／尽量露脸”没有被误读成强制全员名单。
- [ ] 夜景来自活动本身，而不是为宝箱吸血鬼蜗改写生活愿望或添加尾声。

- [ ] 没有使用萝卜蜗或未经确认的高风险库存角色。
