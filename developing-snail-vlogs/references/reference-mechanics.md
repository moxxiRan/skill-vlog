## 0. 与渐进创作流程的关系

本文件与 `ganamao-six-script-deconstruction.md` 是 `developing-snail-vlogs` 的参考基线，不是跳过主题、大纲、角色情节或逐镜冻结的快捷模板。用户要求核对原始脚本时，必须再读取同目录最新版 `干嘛猫脚本分析.md`；本文件只保留已经整理成可执行规则的内容。

当前参考样本是 **三条最新详细时间轴**。所有新稿都要迁移机制而不是复制路线、对象、角色岗位、品牌、原句或相同对象加相同落点的笑点。

## 1. 证据口径与最新样本

### 1.1 来源完整性

读取原始文件前记录路径、行数和哈希，并确认标题 `脚本一`、`脚本二`、`脚本三` 均存在。当前权威源为 229 行，三条时间轴表格行数分别为 49、29、38。写作 skill 的打包副本必须与它逐字一致；副本不一致时报告差异，不把旧副本当成另一套样本。

源稿有一处时间戳笔误（脚本一第 64 行写作 `02:28 - 00:30`），脚本标题外层时间也不总能与表内相对时间直接拼接。制作中以当前逐镜和相对时间为准，不把外层段落时间换算为新稿绝对时间。

### 1.2 三条样本的可核实事实

| 样本 | 主要节拍 | 机制证据 |
|---|---|---|
| 脚本一：海洋馆一日游 | 生活进入与集合 → 多个海洋对象的观察／错读／互动 → 水上项目失控 → 湿态烘干 → 购物身体梗 → 花车烟花 | 49 行详细时间轴；POV、对象特写、朋友互损和共同夜景交替 |
| 脚本二：五一山水漂流与乡村旅游 | 预览与出发 → 山景民宿和清洁需求 → 晚安 → 装备与叠爪 → 急流、旋转、拖鞋后果、湿态 → 躺平、乡村空镜、瀑布回收手机 | 29 行详细时间轴；生活问题触发植入，高潮留下可持续身体／道具状态 |
| 脚本三：游乐园与景区深度体验 | 骑车邀约与群聊 → 聚餐和身体插曲 → 民宿、UNO、除螨与晚安 → 商场／展会／电玩城／密室 → 烤鱼压惊、KTV、枕头大战、夜景 → 游乐园项目逐级升级、花海、碰碰车、烟花 | 38 行详细时间轴；按当前表格作为一条完整路线分析 |

源稿前后两套分析有重复和局部冲突：一处写“无人类语言解说”，另一处推测人类配音和口型；一处写平均 2—3 秒切镜，另一处写 1—2 秒。它们只能作为未验证观察。项目当前的确定边界是：语义只交付五列表台词分镜组别对应表，不生成字幕轨；Seedance 净输入不含语义对白、真人旁白或自动文字。

## 2. 三条脚本的机制地图

### 2.1 共同骨架

> 生活动作／邀约 → 集合与移动 → 活动本身证明“值得参加” → 多个局部事件 → 环境或设施升级 → 高潮结果 → 持续状态、处理恢复、关系反应或安静余波 → 共同环境／收镜动作

这只是功能顺序，不是固定地点、镜头数量或每集必备清单。题材没有物理事故时，不强行制造事故；题材没有商业植入时，不补产品段。

### 2.2 脚本一：对象奇观与湿态收口

- 先用起床、洗澡、吹毛和地铁集合建立 Vlogger 的生活状态。
- 水族对象轮番出现，但每个对象只承担一个可读的观察、错读、模仿、亲近或朋友反应。
- 白鲸、企鹅、海豹、水獭等对象的真实行为与猫的拟人判断并置，画面负责证明荒诞。
- 激流勇进把舒缓参观升级成速度、水花和湿毛；烘干、纪念品和墨镜滑落让结果继续存在。
- 花车、烟花和五只猫的共同停留完成自然结尾。

### 2.3 脚本二：问题触发植入与体验—后果循环

- 高能漂流预览可以先建立承诺，但必须回到开场、开车和民宿把因果补完整。
- 喷嚏、灰尘和浮毛先出现，扫拖吸尘器、梳毛吸头和基站才有生活理由。
- 漂流按“穿装备／叠爪 → 逞强与自保 → 急流和滑道 → 旋转 → 拖鞋漂走 → 湿透”逐步升级。
- 甩水、整理羽毛、烘干、躺平和乡村空镜把刺激降回共同生活；瀑布前回收手机是行动性收镜。

### 2.4 脚本三：社交情绪接力与设施升级

- 骑车邀约、微信弹窗和客厅集合先建立“想和朋友出来玩”的普通愿望。
- 烤肉和蒜蓉酱先给满足，随后用身体插曲、回民宿、UNO 和梳理羽毛切出熟人关系。
- 民宿床铺和灰尘触发除螨；商场、展会、电玩城和密室让地点变化始终由行动连接。
- 密室惊吓自然接到烤鱼压惊、KTV、枕头大战和夜景，不把情绪重置成说明文字。
- 游乐园从木马、咖啡杯到过山车、飞椅和碰碰车逐级升高；猫头鹰的平静与其他角色的尖叫形成同一设施内的反应差异，花海和烟花负责降速。

## 3. 时间、视听与镜头节奏

### 3.1 密度变化

三条时间轴都把短观察、动作标签、对象特写和朋友接话压在高密度段中，但也保留乡村风景、花海、夜景和烟花等长停顿。不要强制每镜 1—2 秒、2—3 秒或固定字数；以动作能否读懂、状态是否需要保持和笑点是否完成为准。

### 3.2 画面语言

源稿的积极风格证据包括：超现实写实材质、真实环境与荒诞拟人行为的冲撞、湿毛与水花等物理反馈、夸张微表情、超广角／鱼眼 POV、自然手持颠簸、触屏／遮镜头等屏幕交互，以及高饱和明亮的治愈色彩。蜗牛稿应写成具体可执行的场景、摄影机和状态，而不是只写“可爱、治愈、电影感”。

### 3.3 声音边界

原稿同时出现“喵叫、BGM、短字幕”和“人类配音、口型对齐”的二手推测，不能把其中一条当成原作者硬规范。项目只在逐镜事实中记录环境声、音乐、物理音效和必要的非语义短促反应；语义台词由唯一五列表承载，不生成字幕轨或另行写配音脚本。

## 4. 桥段模型

### 4.1 总体公式

事件型桥段至少写出：

> 主动动作 → 环境／物体／身体变化 → 即时反应 → 可见结果／持续状态 → 处理、关系反应、继续体验或收口

准备、满足、空镜和呼吸段可以由动作状态、感官价值或情绪停顿成立，但不能用台词独自补出缺失的因果。

### 4.2 体验—后果循环

适用于急流、旋转、风、水、速度、碰撞或其他确有施力的题材：先写正常准备和不同判断，再写环境施力、身体／道具变化和同伴反应，最后留下湿、乱、掉落、变形或疲惫等可见状态。没有实际施力时，不要套用事故模板。

### 4.3 观察—类比循环

适用于动物、展品、食物、设施或陌生物体：正常观察／提问 → 针对具体对象的错读或类比 → 朋友纠偏或画面反证 → 动作／切镜收口。神回复必须有对象和设置，不能随机堆网络词。

### 4.4 呼吸段

吃饭、散步、睡觉、梳理毛发、躺平、风景、花海、夜景和烟花不是“无内容废镜头”。它们证明活动值得参加，划分跨日行程，保存高潮后的持续状态，并给下一个高密度段落留对比。呼吸段也必须有具体动作或可读状态。

### 4.5 画面事实与台词视角

画面负责对象、动作、顺序、接触、变化、结果和持续状态；台词负责角色此刻注意什么、如何判断、如何回应朋友、如何短暂命名或如何收镜。画面显示墨镜滑落，台词可以写角色的判断，不应只复述“墨镜滑落了”；画面没有请求、事故、道具或后果，台词不能凭空增加。

## 5. 角色呈现

### 5.1 源稿可确认的视觉方法

猫样本用牛仔帽、兔耳帽、头盔、翅膀、绿色触角等稳定外观标识，让观众在高密度剪辑中迅速识别角色；行为变化则来自当前事件中的选择。项目蜗牛应使用 `cast-policy.md` 中冻结的正式角色名和稳定视觉特征，不复制猫的配饰或岗位。

### 5.2 蜗牛迁移原则

- Garden 是固定主角和掌镜者，但仍可在具体事件中犯错、逞强、犹豫或被朋友纠偏。
- Beer、麦当劳蜗、侦探蜗牛、宝箱吸血鬼蜗和 Golden 只在当前故事有自然在场理由时出现；不要为凑齐角色而补任务。
- 角色差异要写成选择、动作、反应和关系动作，例如抢先、跟随、自保、模仿、帮忙或补救；一次性动作不能自动成为永久口头禅或性格。
- 同一角色连续多集重复“同一刺激＋同一反应＋同一笑点”时，必须改写选择或明确回调结果。

## 6. 生活化植入

### 文件事实

脚本二的清洁植入由灰尘、喷嚏和猫毛触发；脚本三的除螨仪先在民宿床铺使用，再通过品牌展会打卡和重复吸床形成回声。产品功能通过推、吸、梳、自动清洁或身体反馈在画面中发生。

### 可迁移公式

> 已出现的生活问题 → 角色主动拿起或操作产品 → 功能造成可见变化 → 同伴／身体反应 → 继续生活

不得把产品说明、品牌口号或未出现的需求塞进台词或视频提示词；若没有真实问题，就省略植入。

## 7. 结尾与开场

### 开场

开场可用起床、洗漱、骑车、群聊、预览或集合，但必须迅速建立“今天为什么值得一起出去”。预览是可选的剪辑策略，不是每集规则；预览之后仍要回到正式起因。

### 结尾

高潮之后至少选择一种题材适配的回收：持续身体／道具状态、处理恢复、关系反应、继续体验、风景降速、夜景／烟花或掌镜回收。不要用友情总结代替可见收镜动作。

## 8. 不可照搬项

- 不复制海洋馆、漂流、烘干、过山车、花海／烟花等整组路线或相同的顺序组合。
- 不复制 Q 币、`稳重`、`烘干基`、拖鞋后果等原句和同构落点。
- 不把牛仔帽白猫、兔耳三花、狸花舞蹈或猫头鹰飞行当成蜗牛固定职业任务。
- 只使用最新版源稿中可核实的路线、对象和动作，不把其他版本或外部摘要当成当前脚本事实。
- 不把不同地点、不同对象或更换天气道具当成新机制；必须改变核心动作、环境施力、结果或关系变化。

## 9. 最小参考模型

新稿至少应能回答：

1. 普通朋友为什么愿意参加这项活动？
2. 途中有哪些具体主动动作和可见变化？
3. 哪个局部事件让角色选择产生差异？
4. 高潮的结果是什么，之后如何持续、处理或降速？
5. 蜗牛身体／环境关系带来的不可替代点是什么？
6. 逐镜如何写清真实场景、摄影机、焦段、景别、正式角色名、动作关系和一个明确最后帧？
7. 台词是否只补视角并进入唯一五列表，资产是否按组稀疏输出？

任一答案只能靠台词解释、靠固定岗位补齐或依赖未生成资产时，回退到最早缺口。

## 10. 分阶段硬性验收

### 10.1 主题冻结前

- 活动换成人仍值得参加。
- 至少有 2—3 个不同的可见观看承诺；每个写成 `主动动作 → 环境／物体／身体变化 → 可见结果／收口`。
- 至少一个蜗牛不可替代点，并说明与三条最新脚本的具体路线、对象和笑点差异。

### 10.2 大纲冻结前

- 行程只是骨架，至少有多个局部事件；事件型桥段写清动作、变化、反应、结果。
- 高潮闭合，且有持续状态、处理、关系反应、继续体验或安静余波中的适用项。

### 10.3 角色情节冻结前

- 每个保留角色有在场理由和当前选择；差异来自同一事件的判断或关系动作。
- 无固定岗位、平均分配露脸或没有跨集证据的永久性格。

### 10.4 逐镜视觉冻结前

- 每个大纲桥段有兑现镜头；每个镜头一个主要动作中心。
- 写清场景拓扑、摄影机方位／光轴、数值焦段、景别、正式角色名、动作顺序、接触触发、声音、结果和最后帧。
- 全片连续镜头号完整；只有用户明确采用兼容 Seedance 组级流程时，才补充视频组别边界、组内顺序和 `组别-镜头` 映射。B 模式首帧／视频提示词不依赖组映射。

### 10.5 下游交付前

- 台词表由 `writing-snail-vlog-subtitles` 唯一写入，只有五列表，不生成字幕轨。
- 兼容分支的生图资产按视频组稀疏列出；未使用的 `A-CHAR`、`A-SCENE`、`A-PROP`、`A-FX`、`A-FRAME` 不建立 ID；`A-FRAME` 一图只绑定一个镜头、一个静态时刻和一个构图。B 模式逐镜首帧不归入稀疏资产清单。
- B 模式每个真实镜头有一条独立首帧提示词，首帧已选且已验证后才建立同镜视频提示词；视频 prompt 只让首帧动起来，不重设计第二构图。兼容 Seedance 净输入中的每个提示词镜头也只对应一个真实镜头，不暗含第二构图；两类输入都不混入台词或整段生图提示词。
- B 模式首帧和视频、以及兼容 Seedance 组中的真人路人，只能出现脖子以下部位；真人人脸、头部和面部轮廓均禁止。参考样本里的“路人”只说明公共空间尺度，不放宽本项目最新人物裁切约束。
