## 1. 使用说明与证据边界

当前权威源是同目录的 `干嘛猫脚本分析.md`。最新版只有 **三条明确的详细时间轴**，标题分别位于源稿第 50、107、143 行；没有独立存在的“三份语义概要”。三条时间轴的表格行数为：脚本一 49 行、脚本二 29 行、脚本三 38 行，合计 116 行。行数只描述源稿颗粒度，不是新稿镜头配额。

本文件把源稿中的可见事实拆成可执行的故事、角色、镜头和台词机制。证据分为：

- **原文事实**：能直接回指源稿的画面、台词、时间戳或分析段落。
- **跨脚本归纳**：三条时间轴反复出现、可迁移的关系或节奏机制。
- **项目工作推导**：为蜗牛 Vlog 和 Seedance 生产制定的执行规则，不冒充干嘛猫原作者的公开流程。
- **用户约束**：本项目不生成字幕轨、SRT、VTT、Cue 或配音稿；语义文字只写入唯一的五列表“台词分镜组别对应表”。

源稿内部有需要保留的不确定性：平均切镜速度一处写 2—3 秒、一处写 1—2 秒；声音分析一处写无人的语言解说，另一处又推测人类配音和口型对齐；脚本标题使用全局时间段，而表格内部从 `00:00` 重新计时。它们只能作为待核实观察，不能变成硬配额。制作时以逐镜画面、用户约束和当前冻结稿为准。

## 3. 三条脚本共同的创作机制

### 3.1 活动先值得参加，行程只是骨架

开场从起床、洗漱、骑车、群聊、集合或出发进入，而不是从景点说明开始。活动即使换成人类朋友也应值得拍：看动物、旅行、聚餐、游乐园本身先提供观看承诺，蜗牛的荒诞行为再放大它。

### 3.2 内容来自短小的局部事件

行程串联场景，局部事件提供笑点和角色。通用结构是：

> 主动动作／判断 → 环境、物体、设施或身体变化 → 同伴即时反应 → 可见结果或关系接话 → 直接收口

例如误把海星当成别的对象后被纠偏、逞强进入急流后掉拖鞋、密室受惊后吃烤鱼压惊。事件不能只靠台词解释；画面必须显示触发、变化和结果。

### 3.3 同一事件中的反应差异比职责标签鲜活

角色可以认真、错读、纠偏、逞强、犹豫、自保、模仿、跟随或补救，但差异必须来自当前选择。不能把“组织者、清洁者、司机、舞蹈者”等当成蜗牛的永久岗位，也不能为了让每个人露脸而补动作。

### 3.4 高潮要有结果，结果要继续存在

海洋馆水上项目后毛发湿透并烘干；漂流后拖鞋漂走、全员湿透、整理羽毛和躺平；游乐园高强度项目后转入花海、烟花和告别。没有物理后果时，用关系反应、继续体验、情绪降速或安静余波收口，但不能让高潮停在未闭合的尖叫。

### 3.5 真实环境与荒诞拟人并置

源稿反复使用写实地铁、民宿、餐厅、商场、游乐园、水族馆和山景，再放入直立行走、用筷子、开车、操作家电、玩设施的拟人行为。材质、毛发湿态、水花、风力形变和道具接触要可见；微表情负责把荒诞行为变成“像朋友在生活”。蜗牛项目应迁移这种冲撞关系，不复制猫的帽子、品牌或职业。

### 3.6 POV、环境远景和对象特写按信息交替

掌镜者的 POV、手机／GoPro 的广角或鱼眼畸变、手持步态颠簸、摸镜头／遮镜头，与环境远景、对象特写、群像结果和单个反应切换。POV 是叙事位置，不是装饰。每个真实镜头只保留一个主要动作中心；一个视频组可以包含多个真实切镜。

### 3.7 节奏是密度变化，不是固定秒数

短小动作和对象特写形成高密度段，脚本二的乡村空镜、脚本三的花海／夜景则提供 7—11 秒左右的降速停顿。不要把源稿中互相矛盾的“1—2 秒”和“2—3 秒”固化为镜头配额；按当前动作是否读得懂、笑点是否落地和结果是否需要保持来定时长。

### 3.8 软性植入必须进入生活因果

脚本二先有喷嚏、灰尘和浮毛，再出现扫拖吸尘器、梳毛吸头和基站自清洁；脚本三先有民宿床铺、除螨需求和同伴反应，再出现除螨仪、品牌展会和后续复用。蜗牛项目若有产品，只能解决画面中已经出现的问题，并通过动作展示功能，不得单独插入产品说明镜头。

## 7. 迁移到蜗牛 Vlog 的规则

1. 主题先写“普通朋友为什么愿意参加”，再写蜗牛身体、黏液、触角、壳体、爬行速度或环境尺度带来的不可替代点。
2. 每个观看承诺都要写成 `主动动作 → 环境／物体／身体变化 → 可见结果／收口`；不同地点或不同对象不算不同机制。
3. 大纲和逐镜使用真实环境加拟人行为的冲撞，角色差异来自同一事件下的选择，不复制猫的固定岗位。
4. 高潮镜头后保留持续状态、处理、关系反应、继续体验或安静余波中的适用项。
5. 逐镜字段写清场景、摄影机方位／光轴、数值焦段、景别、正式角色名称、动作关系、声音和最后帧；一个提示词对应一个真实镜头，不能暗含切换到另一构图。
6. 兼容分支的生图资产按视频组稀疏列出，只写确需提前生成的场景、道具、角色变体、特效／材质；未用类型省略。B 模式逐镜首帧不归入稀疏资产清单。复杂场景确有首尾帧需求时才使用 `A-FRAME`，一图只绑定一个镜头和一个静态构图。

## 8. 台词表、兼容资产与兼容 Seedance 边界

- 台词只由 `writing-snail-vlog-subtitles` 写入唯一五列表：`组别-镜头｜时间戳｜景别／画面内容｜台词｜动作与音效细节`。不生成字幕轨、SRT、VTT、Cue 或独立配音稿。
- 画面列和动作音效列只能引用冻结逐镜；台词写观察、判断、关系和短标签，不新增动作、道具、因果或后果。无自然台词时写 `（无）`。
- B 模式逐镜视频 prompt 只描述已验证首帧的一个主动作，不重设计静态构图；兼容 Seedance 净输入只描述冻结的真实镜头、空间和动作，不混入台词或整段生图提示词。两类视频输入都不隐藏第二构图。
- 兼容分支资产清单只列实际有图片依赖的组；无依赖的组省略，不建立“无需额外生图”空行，也不强制填满 `A-CHAR`、`A-SCENE`、`A-PROP`、`A-FX`、`A-FRAME`。
- 首帧、逐镜视频和兼容组中的真人路人只允许脖子以下部位；禁止真人人脸、头部和面部轮廓。样本中的路人／游客描述是公共空间证据，不是对本项目人物可见范围的授权。
